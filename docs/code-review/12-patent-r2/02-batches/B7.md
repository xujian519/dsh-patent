## 已排除候选

| 候选 | 排除理由 |
|---|---|
| `role-contracts.ts` 的角色描述与 `worker-contract.ts` 的 worker 描述重复 | 角色是「作业立场单元」、worker 是「专业处理单元」，同一角色的描述常在后者的基础上追加立场约束；合并会把立场与工序耦合成一份数据。 |
| `role-contracts.ts` 每次调用重建 `defaultPatentWorkers()` / `defaultRoleContracts()` | 返回新数组避免调用方修改共享目录；目录很小，分配成本低于共享可变状态的维护成本。 |
| `flow-graph.ts` `topologicalLevels` 的孤儿节点检查与 `validate()` 的环检查各自报错 | 两个方法服务不同调用方：`topologicalLevels` 在无法调度时抛出，`validate()` 返回问题列表；合并会改变公开方法的失败契约。 |
| `workflow-dag.ts` 的 Mermaid 节点 id 未转义 | 内置 manifest 的阶段 id 均为安全标识符；模型自编 `flexible_plan` 的阶段 id 未在创建时限制字符集，属于既有输入约束缺口，不在本批扩面。 |
| `docket-issue.parseIssueDispositions` 对 `JSON.parse('null')` 抛 TypeError 而非 `IssueDispositionError` | 输入是随包资产，不是外部或用户数据；资产缺失/损坏在装载期已经 fail-loud，错误类型差异不影响处置。 |
| `patent-teams` 的 `team.js`/`event-types` 双模块拆分 | `event-types.ts` 必须保持零运行时导入，供浏览器程序加载 `SessionEventMap`；合并会把 Host 侧的 `Context` 增广带进浏览器。 |
