## 采纳并修复（5 条）

- **F-PAT-073**（最重要）缓存包装器丢弃 `timeout` 与 `signal`：`patent_metadata` 公开了 `timeout` 参数并传了取消信号，但生产路径走缓存包装器，两个字段在运行时被静默丢掉——调用方设 5 秒无效、取消要等引擎默认 30 秒（最坏约 90 秒）。修在 `patent-data` 的包装器，透传且不进缓存键。
- **F-PAT-074** 留档的「读—校验—追加」不是原子操作：并发留档会让同一产物登记两次或给同一旧版挂两个后继。改为在 `withFileLock` 内重读后追加。
- **F-PAT-075** 重试的退避不可中止：取消后仍多发一次上游请求。退避改为监听 `signal`。
- **F-PAT-076** PDF 下载的 `timeoutMs` 文案写「整体执行超时」，实现是每腿预算且 CNIPR 腿有 90 秒下限。改文案，同步工具目录与 `patent-oa-response` 的工具 schema 快照。
- **F-PAT-077** 非 `Error` 抛值渲染成 `[object Object]`：改用 `errorMessage`。

## 未修（2 条）

- **F-PAT-078** 无效宣告结论的 `claimNo` 缺省 0：损坏字段会被渲染成「权项 0」。修法要改读取侧的丢弃语义与测试期望。
- **F-PAT-079** 索引存储的 upsert 只在进程内串行：跨进程并发会静默丢条目。修法同样是 `withFileLock`，需连同共用该模块的附图与化学索引一起改。

## 观察（不构成发现）

- `knowledge-note-file-writer` 的判重与写入之间是 TOCTOU：并发保存同一内容会都报 `inserted`，但写入内容相同，无数据损坏，只是幂等报告口径。
- 上游自由文本（标题、错误串）未转义就拼进模型可见 Markdown：当前都渲染成标题与 bullet（无表格），注入面有限，记为健壮性缺口。
- `recognize_chemical_structure` 是诚实的占位：本构建未接入识别引擎，工具描述直接告诉模型「不可用、请走人工复核」，11 行索引写入分支因此被 `v8 ignore`。不是缺陷，但占着一个工具位。
