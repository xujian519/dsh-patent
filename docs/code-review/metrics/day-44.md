## 重跑规则

- 模型名、模型 id、provider 或思考模式任一变化：试点与扩域全段重跑，旧基线作废。不能把新旧模型的读数放在同一张表里比较。
- 系统提示词变化：全段重跑。提示词是选择与拒绝读数的一部分，不能只重跑失败题。
- 题库题干、可接受工具、禁止工具或外部判定变化：该层题库作废，直接调用、脚本场景与真实模型三层一起重跑；旧读数保留为历史记录，标注日期与冻结文本。
- 工具面变化：工具增删、工具描述或 JSON Schema 变化都算工具面变化；试点与扩域全段重跑。只改一个工具的描述也要整段重跑，因为选择读数看的是首个相关调用。
- 单价变化：只重算费用列，不重跑模型；重算后的费用与旧费用分列，注明单价日期。
- 仓库行为变化：agent-loop、工具结果格式、会话事件或 provider 适配器变化时，按影响面重跑；不能确认影响面时按全段处理。

每次重跑前把当次的模型、提示词、题库、工具面、单价与环境写进当天 `metrics/day-NN.md`，再开始采样。重跑后的新基线追加记录，不覆盖旧文件；旧基线仍可按日期与冻结输入复核，但不再作为当前读数。

## 为什么维持周期评测

- 结果不确定。试点 60 次里有 1 次超时，按题一致率均值 90.0%；同一题的三次结果可能不同。
- 成本高。两批合计 162 个已测样本，token 费用 3.8464 元；每次全量重跑还要数小时墙钟。
- 依赖真实 API。CI 没有密钥与计费环境；没有密钥时只能跳过，跳过不能记成通过。
- 读数会随模型版本漂移。把模型相关读数设成阻塞 CI，会让上游模型更新直接变成仓库红灯。

周期评测的触发条件是模型或提示词变化、下一周期开始，或明确要求复核；不按每个 PR 触发。评测结果只用于定位选择、拒绝、延迟、成本与上下文占用的变化，不阻塞合并。
