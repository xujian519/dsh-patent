## 今日维度与范围

本日开 P5（[#937](https://github.com/xujian519/dsh-patent/issues/937)），只做 D39 的选族：按 [day-12.md](day-12.md) 的直接调用通过线与 [day-34.md](day-34.md) 的扩域通过线，逐格核对 11 族，列出低于线的族，并固定十列口径。本日不调用真实模型，不重跑直接调用与脚本场景；试点与扩域已经记过的分子分母原样引用，不在此重算，也不改写成百分比排名。

## 通过线与判定规则

[day-12.md](day-12.md) 的「观察基线」就是直接调用层的通过线，「低于任一格记为低于基线」。该表的格子是语法、可解释性、残留、非法 JSON、类型错误、缺必填、路径、超长、注入。[day-34.md](day-34.md) 的扩域通过线是「语法通过、语义成立、外部判定成立三列同时成立」，27 道实测题里 22 道通过。

P1 通过线没有选择、拒绝、墙钟、费用、上下文、恢复、资源这七列。按严格规则，这七列不参与选族，只在深挖时按十列记录；它们读得再低，也不会把一个族带进或带出名单。这一点是 P5 与「按十项里最差的列选族」的口径差，先写在这里，避免后面把选择准确率当成唯一标准。

族的归属按样本落点判断：低于线的格子里的样本属于哪个族，就把该族列入名单。一个族只要有一格低于线就入选，没有加权，也没有「主要低于线」的排序。

## 不在名单的族

检索与法律状态（RET）的直接调用各格都在线；P-RET-03 的 10 条命中是 [F-PAT-056](../05-findings.md) 的产品缺陷，但不落在通过线的任何一格，按严格规则不选。它的真实模型外部判定 3/12 在 P1 没有对应格子，读数已经留在 [day-27.md](day-27.md) 与 [scorecard.md](scorecard.md)。

视频（VID）的真实模型读数是 11 族里最差的一组：成功 3/15、选择 6/12、拒绝 0/3。但视频族的可调用题在扩域直接调用里都通过三列，P1 与 day-34 都没有给选择、拒绝、费用设通过线，所以严格规则下它不在名单。这不是说视频族不需要处理，而是说它的偏差在「没有通过线」的列里，留到 P6 按十项复盘的读法处理，见 [day-42.md](day-42.md) 的边界说明。

附图、文档交付、知识与分析三族没有任何格低于线。

## 本日结论

名单是 6 族：LAW、SPC、CLM、FEE、WF、LGL。低于线的直接调用格子集中在六个工具的边界：`law_verify` 的 schema 不表达二选一、`validate_specification` 的 `text` 不是必填、`render_patent_document`/`build_patent_filing`/`verify_patent_filing` 的预期失败没有 `error.code`、`claim_lint` 没有长度上限。扩域三族的三列不通过都来自冻结判定差，不来自工具执行错误。

本阶段预计新增三条代码发现：LAW 与 LGL 共享的核验参数契约一条，SPC 的 `validate_specification` 一条，WF 的 `patent_plan_task` 参数适用范围一条。是否成立以 [day-40.md](day-40.md) 至 [day-42.md](day-42.md) 的证据为准，本日不登记。
