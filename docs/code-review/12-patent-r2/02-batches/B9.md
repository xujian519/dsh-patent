# B9 patent-tools 检索与数据

执行日期：2026-11-29。主维度：质量。

## 范围与口径

README 批次表记本批 42 个 `src` 文件；实测 43 个，差异来自两次文件变动：

- 第一轮 B4「检索与数据通道」的 42 个文件是第一轮的完整口径；其中 `internal/slop-engine.ts` 已在 B3 随 F-PAT-122 迁往 `patent-core/src/quality/slop-engine.ts`，不再属于本包。
- 第一轮未收录、但属于同一通道的两个新模块计入本批：`tool/patent-pdf-download-fallback.ts`、`tool/patent-pdf-download-transfer.ts`。
- 因此实测 41 + 2 = 43 个文件：`tool/` 17 个（含上述两个新模块）、`tool/internal/` 21 个、`internal/` 4 个、`chemistry/index-store.ts` 1 个。
- `00-coverage.tsv` 的 `batch` 列对旧文件仍标第一轮 B4、对新增文件标 B9，与本轮批次表不是同一口径；沿用 B4/B7/B8 做法，未改台账。

## 已排除候选

| 候选 | 排除理由 |
|---|---|
| 主通道抛错、第二通道也失败时，CNIPR 的失败原因不进入抛出的错误 | 抛错路径没有 `channelsConsulted` 输出，错误消息只承载主通道原因；把第二通道告警拼进任意抛错会改变现有错误文案契约，收益不足。 |
| `patent-pdf-download` 续传只校验 `size`、不校验 `sha1` | 见 S-PAT-B9-3：字段已在 MANIFEST 中，是否改为校验或删除需要单独口径；本批不混入缺陷修复。 |
| `internal/index-store.ts` 的跨进程 upsert 与 `invalidity-json.ts` 的 `claimNo` 缺省 0 | 已分别由 B1 决策分配到 B11（F-PAT-079、F-PAT-078），本批只复核现状，未改。 |
| `patent-metadata` 的 CNIPR 查询不按页大小分批 | CNIPR 通道自身按 `CNIPR_SEARCH_PAGE_SIZE` 翻页并在通道层收敛上限；工具只需精确匹配。 |
