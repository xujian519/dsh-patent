# 质量门禁

输出前必查。任何一项不满足即把产出打回补证，检查不过不得交付。

## 检查清单

1. 免责声明在场：面向用户的专利分析输出必须含免责声明。
2. 法条核验：先用 `law_verify` 过一遍交付物里的每条引用（判定含义与后续动作见 patent-fact-check）；判为「未核验」或「索引中不存在」的，继续用 cnlaw MCP 的 `mcp__cnlaw__*`，或 `patent_case_search` / `web_fetch` 打开原文 / `99-知识库/` 基线核验并记录渠道；判为「与所引命题不符」或「条号超出有效范围」的改写或删除。引用时核一遍、输出前再核一遍；走 REST 兜底时须说明原因。
3. 检索证据链：新颖性/创造性结论有检索报告支撑，每个对比文件已打开验证，公开日早于申请日/优先权日。
4. 数字计算：期限/日期用 `patent_deadlines`、官费与年费金额用 `patent_fees`，命中数与页码以工具返回为准，禁止心算。`patent_fees` 未给出合计时（说明书附加费、延长期限请求费两项按分档收费、索引未记金额），必须按官方收费标准公告逐项核价，不得自行补数或用"约 X 元"表述。
5. 检查清单对照：撰写产物对照权利要求/说明书缺陷检查清单（清楚、支持、充分公开、单一性、修改超范围）。撰写与答复场景的实体判定以 `patent_workflow_run` 的阶段记录为准：`spec_check`（五部分与形式）、`enablement_report`（A26.3 充分公开）、`claim_breadth`（A26.4 概括范围）、`response_check`（驳回理由覆盖）、`amendment_basis`（A33 修改依据）；这些阶段未通过即不得交付。权利要求编号结构另跑 `claim_lint`：编号连续、从权只引用在先权项、多项从属择一引用且不作另一多项从属的引用基础。
6. 反套话与篇幅：披露链 `slop_clean` 是 warn 级——未通过只报告，不阻断交付，不得据此打回；答复链 `slop_gate` 未通过会回退 `draft` 重写，交付稿须为回退后的版本，且正文 ≤ 4000 字可见字符（去空白、不含表格与权利要求全文）。
7. 附图与标号：有附图时，附图标记表在场且与图面、说明书、权利要求逐号一致（《专利法实施细则》第二十一条第二款双向一致：说明书文字部分未提及的标记不得在附图中出现，附图中未出现的标记不得在说明书文字部分中提及，同一组成部分的标记应当一致）；图号位于附图正下方；图面除必需词语外无注释；色彩与落版尺寸符合目标法域（CNIPA / PCT / USPTO）；建队时由制图员角色（`illustrator`）产出并核验，单会话模式下由本会话按同一纪律执行；无论哪种模式都禁止用临时脚本代替 `generate_patent_figure` / `analyze_patent_figure`，自绘或外部 SVG 需要补标号时同样用 `add_patent_figure_references` 而非脚本（脚本产物不进附图索引、不可复查）。**交付前的图面复核走 `verify_patent_figure`**：它逐处判标号是否被线条贯穿、点划线是否被实线覆盖、两个图元是否叠压、相邻零件剖面线是否可区分、内容是否越界、字高是否低于本部署下限——这些缺陷只在画面上看得见，属性表看不出来。字高下限与图面字号取本部署 `patent-tools` 的 `figureMinFontMm` / `figureFontMm`（本所体例：附图页内图内文字为小四或四号；生成时按配置出图，复核按同一下限逐处判定，落版缩放后仍低于下限的图须减字或分图）。
8. 证据附录完整：法条来源（含 law_verify 的判定表与各引用的查证渠道）、对比文件路径、检索式与日期、数字计算依据、检索未覆盖领域显式列出。
9. 对立审查：必要时 subagent_fork 一个对立审查员角色，以审查员视角对交付稿攻击性评审（不清楚、不支持、超范围、缺必要技术特征）。
10. HITL 放行：交付放行前用 ask_user_question 向用户确认；权利要求布局已在 plan-mode 获批（L3 强制确认点）。
11. 正式文档交付：交付文书按 patent-document-polish 走场景→模板映射，矫正（术语/法条引用/数字/编号/称谓）与美化（模板/品牌/A4）已完成、渲染成功（PDF 失败时 HTML 存在并如实说明）；docx 交付额外确认由 md 起草转换而来、修订以 tracked changes 呈现、输入原件未被改动。
12. 放行去重：文档专员的交付放行与收口确认合并为一次 ask_user_question，不重复打扰。
13. 产物与推理分离：交付件里不出现推理过程痕迹——逐步自我推演（"首先…然后…因此"式的判断过程）、内部权衡中否决且与交付无关的思路、对自身结论的复述。中间判断留在工作稿；权利要求与意见陈述直接给结论与论证，不要求"先写出推理再产出定稿"。说明书依实施细则记载的替代实施方式不属此列，按公开充分的要求照常写入。

## 流程

按顺序逐项核查 → 记录不满足项 → 打回补证 → 补证后重新过门禁 → 放行前 ask_user_question 确认 → 用户确认才交付。法条/证据/数字项已由 patent-fact-check 执行时，此处仅核对结论与留痕，不重复执行。
