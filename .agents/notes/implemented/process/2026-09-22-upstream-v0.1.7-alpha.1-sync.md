# Agent Note: upstream v0.1.7-alpha.1 sync

Status: implemented

English | [中文](2026-09-22-upstream-v0.1.7-alpha.1-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.1.6-alpha.2` tag, this merge's base, to the `dsh-v0.1.7-alpha.1` release. Upstream advanced 1299 commits while the fork carried 595 of its own, and the first merge attempt conflicted in 183 paths: 70 on fork-owned surfaces, 52 in client plugin packages, 40 in core packages, 20 in infrastructure and configuration, and one unclassified.

Three of this release's changes met fork content upstream has never seen. Upstream replaced the plugin-declared preset system with a declaration plugin (`@deepseek-ai/dsh-agent-preset`) plus `@deepseek-ai/dsh-agent-preset-registry`, and moved the shipped preset sheets into `packages/bundle/web-app/presets/` where the bundle declares them through `dsh.bundle.patch`; the fork's `packages/preset/agent-presets` package, its `presets/{patent,document}` trees, and the `$DSH_HOME/.agent-presets` user root it read have no upstream counterpart. Upstream also added two gates that judge content only this fork produces — `verify-v3-event-vocabulary`, which compares the frozen V3 event vocabulary against a pinned V3-writer commit, and `verify-no-unknown-casts`, whose committed baseline records upstream's assertions only — plus a `package.json` `files` policy in `scripts/check-workspace-constraints.ts` that derives its expectation per package.

## Decision

- **Upstream's declarative preset system replaces the fork's preset package, and the fork's presets ship from the web bundle.** `packages/preset/agent-presets` is retired: its registry, session, display, and inventory sources fold into upstream's `packages/preset/agent-preset-registry`, and its assets move under `packages/bundle/web-app/` as `presets/{patent,document}.patch.yml`, `presets/{patent,document}{,.zh}.md`, and `skills/{patent,document}/`. The user root `$DSH_HOME/.agent-presets` is read by nothing in the merged tree, and `docs/patent-workbench-tasks.md` re-points every path it had recorded there at the declaration in `presets/patent.patch.yml`.
- **The web bundle publishes the fork's preset assets, and the constraints table records them beside upstream's own entry.** `packages/bundle/web-app/package.json` lists the four guide files and `skills`, and `expectedDshPackageFiles` composes its expectation from `dsh.bundle.patch` plus `packageFileExtras`, so `'@deepseek-ai/dsh-web-app': ['presets/patent.md', 'presets/patent.zh.md', 'presets/document.md', 'presets/document.zh.md', 'skills']` joins the table next to upstream's `'@deepseek-ai/dsh-agent-preset': ['skills']`. Publishing the directory is required rather than tidy: `presets/patent.patch.yml` resolves its skill root with `createRequire(baseUrl).resolve('@deepseek-ai/dsh-web-app/package.json')` and joins `skills/patent` onto that path, so the row that loads the fifteen patent skills follows the installed package.
- **`RELEASED_V3_EVENT_TYPES` takes the fork's twenty V3-writer names.** The fork's V3 writer emitted `agent/request-error`, the three `patent/*`, the nine `patent-teams/*`, and the seven `self-evolve/*` names on top of upstream's 58, and `verify-v3-event-vocabulary` requires exact equality with a V3-writer commit, so the set grows to 78 names. The pin commit id stays in release validation rather than in the source tree; dropping the names would refuse or rename every recorded patent-mode and self-evolve session at migration.
- **The three fork-only message source kinds are qualified as attribution-only.** `docs/persistence-changes/2026-09-22-fork-source-attribution` records self-evolve, sidechat, and patent-teams-report against the accepted format 4 baseline: each kind comes from a producer only this tree ships, no reader outside that producer loses information, and the additions therefore stay same-version instead of requiring format 5. The record states the reader promise per kind rather than granting a general exception for union alternatives.
- **The unknown-cast baseline is the sum of both parents' inventories, then pruned to the merged tree.** `verify-no-unknown-casts` arrived with this release, so a baseline that recorded upstream's 565 files and 1476 assertions had no entry for the fork's inventory (871 files, 2214 assertions) and reported 459 added assertions, none of them new. Rebuilding it as the union and pruning to the exact merged inventory (771 files, 1929 assertions) leaves a baseline that distinguishes an inherited assertion from one this merge introduced. Three sites exceeded both parents and were reviewed one by one: `client.ctx.sessions as unknown as ClientSessions` in `packages/client/ui-session/tests/status-controller.client.spec.ts` (the client program resolves `Context.sessions` to the host `SessionStore`, so a direct assertion is rejected with TS2352; `packages/api/session-controller/tests/client-apply.client.spec.ts` already carries the same cast for the same reason), a `ui-todo-board` board-view case whose operand moved between the parents, and one fixture in `scripts/verify-agent-preset-config.spec.ts`, where the resolver's new `pluginConfigSchema(value)` narrowing step replaced the fixture's cast, so the file adds no assertion.
- **The merge's released-V4 invariants reach the fork's recorded fixtures.** `assertReleasedV4Relationships` requires a `step/start` before the step it opens and rejects a `tool/result` carrying `error` when its message lacks `isError: true`, so four self-evolve fixtures (`packages/self-evolve/self-evolve{,-basic}/tests/*.spec.ts`) move the flag from the content block onto the message and name their error codes, and `scripts/token-economy-baseline.spec.ts` inserts a `stepStart` event into its plaintext fixture. The fork-only `suppression-reasons` gate joins the expected gate order in `scripts/run-gates.spec.ts`.
- **Two merge-induced clones are repaired at their source rather than suppressed.** `jscpd` matched the exported `textBlockParts` in `packages/client/better-sidebar/src/subagent-activity.ts` against `toolResultTextBlocks` in the package's `tool-result-text.ts` (the two lists resolve the same way but join differently at four call sites), and matched a schema-narrowing block in `scripts/verify-agent-preset-config.spec.ts` against the gate's own resolver. `subagent-activity.ts` keeps only `contentText`, `sidechat-transcript.ts` calls the shared extractor directly, and `pluginConfigSchema` becomes an exported narrowing step the resolver and the declaration fixture share, so the gate reports 0 clones with no `jscpd:ignore` marker and no added unknown cast.
- **Upstream's package content is adopted under the fork's recorded name where the fork renamed it.** Upstream's `packages/guard/timeout-policy` arrives with its own changes in this release; the merged tree keeps the fork's `@deepseek-ai/dsh-timeout-guard` name and applies it to upstream's newest `src/index.ts` (the module doc comment and the registered `name`, 13 lines), so upstream's behavior lands without resurrecting the name the fork's rename retired.
- **The desktop family takes upstream's release and re-ports the fork's capabilities on top of it.** The merged `apps/desktop` differs from upstream in 45 files, which carry the fork's brand icons (`assets/icon.*`, `assets/tray*.png`), `src/tray.ts`, `src/print.ts`, `src/bridge-server.ts`, `src/startup-deadline.ts`, the unsigned-packaging and mandatory-update environment handling (`DSH_DESKTOP_UNSIGNED`, `DSH_DESKTOP_MANDATORY_UPDATE_TEST_ORIGIN`) with its `package-target` and `installer-packaging` specs, and the desktop-host composition overlay `apps/desktop-host/config/desktop.cordis.patch.yml` with `desktop-composition.spec.ts`.
- **The version family aligns inside the merge commit.** All 338 fork manifests sat at `0.1.6-alpha.2` beside upstream's `0.1.7-alpha.1`, and the fork's single version mirror `SIDEBAR_SERVICE_VERSION` in the since-removed better-sidebar package's `service.ts` moves with them. `pnpm exec tsx scripts/release/verify.ts --family dsh` then resolves the family: 352 members, one version, publish order resolved.
- **The hygiene gates that read emitted artifacts need a build, and the fork's CI lane already owns one.** `publint`, `built package invariants`, and `node-next types` inspect the publication view built from `lib/`, so a local run on an unbuilt tree reports missing files rather than a merge defect; the fork's `node-hygiene` job runs `pnpm run build` first for exactly this reason.

## Consequences

The fork ships upstream's v0.1.7-alpha.1 baseline with its preset, patent, desktop, better-sidebar, synapse, self-evolve, document, todo-board, and plugin-market surfaces intact: 44 packages exist here and not upstream, and the only upstream package this tree does not carry is `packages/guard/timeout-policy`, whose content lives on as `timeout-guard`. Presets are now declarations inside the bundle that ships them, which means a preset's skills travel with the package that resolves them at activation, and the fork's patent and document presets follow that rule instead of a separate preset package. The two gates born from upstream's own baseline files needed a fork-side inventory before they could judge anything, and both now compare against recorded states rather than absence: 78 V3 names and 1929 cast assertions. The V3 pin commit id is not in this repository, so re-running `verify-v3-event-vocabulary` requires the id from release validation.

## Alternatives considered

- **Leave the fork's guides and skills out of the published web bundle.** Rejected: `presets/patent.patch.yml` resolves `skills/patent` relative to the installed `@deepseek-ai/dsh-web-app` package, so an unpublished directory turns a shipped preset into a row that fails at activation, and the fork's earlier layout published the same guides as `presets/patent/README.md` inside its own package.
- **Prune the unknown-cast baseline from the merged tree on first sight.** Rejected: pruning only proves that nothing is added relative to the baseline it starts from, which here was upstream's file, so every fork cast would enter as if this merge had written it and the three genuinely new sites would be indistinguishable from the 456 inherited ones.
- **Delete the ui-session client-face cast and assert the host type.** Rejected on compiler evidence: in the merged client program `Context.sessions` resolves to the host `SessionStore`, so `as ClientSessions` and `as ISessions` both fail with TS2352 and the direct form fails with TS2339, leaving the double assertion that the fork's session-controller bench already uses.
- **Add a fourth `verify-agent-preset-config.spec.ts` assertion to the unknown-cast baseline instead of extracting the narrowing step.** Rejected: the fixture needed the declaration plugin's schema, which the gate's resolver already reads, so the cast was avoidable rather than compiler-forced; a baseline entry would preserve it as a permanent exception beside the three assertions the compiler actually requires.
- **Restore upstream's `timeout-policy` package name and retire the fork's rename.** Rejected: the fork recorded the rename after the FIXME upstream still carries, and taking upstream's name back would re-open a settled naming decision for no behavior gain, since upstream's source transfers unchanged apart from the name.
- **Restore the fork's `agent-presets` package alongside upstream's declaration plugin and registry.** Rejected: upstream's registry is the only reader of preset declarations in the merged tree, and keeping two preset systems would leave the fork's own discovery, mount, and authoring paths without a consumer.

## Testing

`pnpm run test` runs the full unit suite on the merged tree: 2238 files and 41766 tests pass, and the two remaining failures are environmental rather than merge-caused. `packages/util/http-proxy/tests/install.spec.ts` times out after 5 seconds on this host's DNS latency when run alone as well (the constraint the previous sync recorded), and `packages/patent/patent-tools/tests/figure-freecad-real-render.spec.ts` renders Chinese callout labels through FreeCAD's bundled Python, which encodes `json.dump(..., ensure_ascii=False)` as ASCII when `LANG`/`LC_ALL`/`LC_CTYPE` are empty — the same spec passes 3/3 under `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 LC_CTYPE=en_US.UTF-8`. `pnpm run typecheck` covers both faces (exit 0); `pnpm run lint` reports 0 warnings and 0 errors across 5872 files; `pnpm run duplication` reports 0 clones. `pnpm run hygiene` reports 19 gates passed, 0 failed, 0 skipped, including `constraints`, `publint`, `built package invariants`, `package invariants`, `no new unknown casts`, and `Cordis config`. `pnpm run doc-sync` reports 44 gates passed, 0 failed, 0 skipped, and the corpus-wide pairing check finds 1372 pairs consistent. `pnpm exec tsx scripts/release/verify.ts --family dsh` resolves 352 members at `0.1.7-alpha.1`. `pnpm run persistence-changes --check` accepts the recorded transitions, and `pnpm run verify-persistence-catalog` reports the catalog, both language pages, `known-event-types.ts`, and the schema inventory up to date.
