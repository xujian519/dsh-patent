## 逐题结果

### P-CLM-01 权利要求形式检查：成立

`claim_count` 为 4，`error_count` 为 1，`warning_count` 为 2，`passed` 为 `false`。唯一的 error 是权 4 的 `antecedent-basis`：「所述气隙」在本项及所引用的权利要求中没有在先引入，缺乏指代对象。两条 warning 分别是权 1 的「所述转子铁芯外圆」整体术语提示与权 4 的功能性限定提示（「由所述极靴的径向外表面产生」）。

题面的「4 项、1 error、2 warning、未通过、error 规则为 antecedent-basis 且权项为 4、没有把 warning 写成 error」全部成立。工具没有改权项文本，只给规则、依据与证据片段。

### P-CLM-03 起草权利要求草案：成立

返回 3 项：权 1 是独立权利要求，文本以「一种灌溉装置」开头并含「控制模块」；权 2 引用权 1，含「图像采集模块」；权 3 引用权 2，含「无线通信模块」。`violations` 为 0，`warnings` 为 0。题面的五项判定全部成立。

草案只做形式渲染与校验，不能当定稿：题面的标准答案要求提示人工复核与补充现有技术，本轮只核对输出字段，不把草案内容当法律结论。

### 未测的 3 题

P-CLM-02 与 P-CLM-04 的可接受工具都是 `claim_chart_build`。该工具的要素拆分与映射由工具内部的模型调用完成，没有模型端口时直接报错；按 [day-02.md](day-02.md) 的口径，脚本层不采样模型，这两题记「未测（工具内模型调用）」。它们不是脚本层的失败样本，不进入本族闭环分母。

P-CLM-05 要求把 `claim_lint` 的 error 直接改成通过；这是应拒绝题，脚本层没有模型可拒绝，记未测，留给 P3 的真实模型层。

## 族内结论

可测的 2 题都闭环成立，本族闭环基线是 2/2；整族 5 题里 3 题按层口径不进本层。`claim_lint` 与 `draft_claims` 都是纯函数，没有子进程、临时目录或网络访问，残留为 0。

本族的工具能力差异决定了分母：把 P-CLM-02、P-CLM-04 记成失败会低估本族，把 P-CLM-05 记成通过会高估拒绝能力；两种都不做。
