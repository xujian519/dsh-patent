# ADR-001：案卷文件夹索引

[English](ADR-001-matter-folder-index.md) | 中文

状态：Accepted。日期：2026-11-04。

## 摘要

案卷（matter）留在操作者本机的文件夹里。工作台账本只索引该文件夹。本文记录已接受的决定，不重新打开该决定。

## 背景

专利作业写下的是一个案卷的文件：交底书、检索记录、分析、草稿，以及只追加的 `_matter-log.md`。这些文件就是案卷。再在云端或 `knowledge.db` 放一份正文，会把真源拆成两处。

工作台已经保存任务元数据。若把该数据库，或每个案卷各自的 Cursor 或 git 项目，当成案卷本身，案卷正文就会离开操作者的磁盘，仓库也会被拆成许多个。

## 决定

- 案卷真源是操作者 Mac 上的本地工作根目录（work root）。
- 工作台只是一条文件夹索引：元数据加上 `workspace_path`。
- 案卷文件正文不进云端，也不进 `knowledge.db`。
- 一个仓库承载多个案卷。不要为每个案卷新建一个 Cursor 项目或一个 git 项目。
- 工作根目录保持可配置，不是唯一硬编码路径。其默认语义与典型值是 `/Users/xujian/工作`。一个案卷是该根目录下的 `<案号>/` 目录加上 `_matter-log.md`。
- 账本是 `~/.dsh/workbench` 下的 SQLite。`knowledge.db` 不是案卷库。桥接可以读取案卷目录上的投影。把这些投影写回案卷目录，不是账本。

## 后果

- 新建案卷按四步进行，[README](../../README.zh.md) 与[专利快速开始](../user/guide/patent-quickstart.zh.md) 写明了这四步：在工作根目录下建文件夹，扫描进工作台账本，用同一仓库打开该案卷，书写落在该文件夹的磁盘文件上。
- `workbenchCaseRoot` 仍是工作根目录的配置字段。未配置时，`workbench_link_patent_case` 仍回退到 `<cwd>/patent-workspace`。该回退不是案卷真源。应把该字段设成本机工作根目录。
- `patent-matter` 与 `patent-workspace-layout` 两个 skill（技能）描述工作根目录，以及单个案卷内部的目录。它们不要求另建一棵 `patent-workspace` 树，也不要求每个案卷一个仓库。

## 不在范围内

本决定不加入案卷全文或向量检索、云同步，或多所共享。本决定不把案卷正文迁入数据库，不重写桥接里案卷与根任务的双轨，也不重做工作台界面。

## 遗留风险

下列事项留给后续 ADR。本文不为此扩大产品范围。

- 案卷与根任务双轨。桥接仍把案卷投影成根任务和阶段任务。这些行里哪一行与 `_matter-log.md` 并列作为权威，尚未决定。
- 多案卷工作目录不一致。一个仓库服务多个案卷目录，会话工作目录可以不同于正在写入的案卷目录。
- 本地路径检查。未配置的 `workbenchCaseRoot` 回退 `<cwd>/patent-workspace`，以及只接受这棵相对目录的检查，会忽略已配置的工作根目录。
