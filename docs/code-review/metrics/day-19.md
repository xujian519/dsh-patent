## 逐条说明

### P-LAW-03 超时：已恢复

首次调用按注入返回 `tool_timeout`。恢复调用在原参数上增加 `notice`，内容与待检文本相同，触发双输入规则的就地解析；`MECH-INV-001` 仍然命中，消息仍是「结构要素不完整：缺失 作用或技术效果（置信度 67% < 75%）」，结果末尾仍有「评估输入: text 18 字 · sha256:77acce…」行。题面的四条判定成立。

`notice` 是题面参数之外的新增输入，恢复后违规总数仍为 11 条，没有把 MECH-INV-001 挤掉，也没有把规则命中改写成法律结论。

### P-LAW-01 空结果：已恢复，并暴露假闭环风险

首次调用成功，但 `findings` 为空、`counts.valid` 为 0。题面要求两条 `valid`，外部判定不成立；只看 `tool/result` 的非错误状态会把它写成「核验通过」，这是假闭环。

恢复调用改用 `references: ['专利法第22条第3款', '审查指南第二部分第四章3.2.1.1']`，两条都判 `valid`，`blocked` 为 `false`，`counts.valid` 为 2，第一条的 `law/article/paragraph` 与第二条的 `sectionPath` 都对。外部判定成立。

空投影是脚本层对没有数据 seam 的工具做的边界注入，不是工具自身返回空；它测的是「恢复计划会不会把空成功当完成」，不改变 `law_verify` 的实现口径。

### P-LAW-04 取消：已恢复

首次调用按注入返回 `tool_aborted`。恢复调用增加空的 `figure_analysis: []`，30 项清单仍全部返回，`passed` 为 `true`，5 项 pass、0 项 hit、25 项 manual；`MECH-DC-001` 与 `MECH-DC-021` 仍是 manual 且带原因。题面判定成立。

空数组没有提供可用附图分析，所以 MECH-DC-001/025 没有被误判成通过；这一条也验证了「空输入不等于通过」的行为。

### 假恢复与重复检查

三次注入都没有原样重放失败调用；每次只有 1 次恢复调用，低于 2 次上限。恢复后的外部判定由字段逐条核验，不是由工具的成功标志推断；没有「宣称成功而外部判定不成立」的样本。

## 族内结论

本族 3 种注入全部覆盖，3/3 已恢复；1 次空结果注入属于「成功但外部判定不成立」，与 P-RET-01 的空结果样本同型。没有同名同参数重复、没有超过 2 次的重试、没有假恢复。

三次调用都只读随包资产，没有子进程、网络或临时文件。残留为 0。
