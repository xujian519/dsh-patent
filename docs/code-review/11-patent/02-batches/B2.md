## 发现（4 条，均已修）

- **F-PAT-064** 规则引擎「全部通过」报告用 `join('')`，模型看到一整行串行标题。
- **F-PAT-065** 节点硬上界在截止前最后一毫秒把 `remaining` 算成 0，而 0 的语义是「无上界」。
- **F-PAT-066** 充分公开子图把两个 `string[]` 状态键按字符串读取：缺失章节恒显示「（无缺失）」，领域特殊要求整段消失。
- **F-PAT-067** 数值范围节点的 LLM 调用不转发 `signal`，取消后仍等在途请求。

修复后 `packages/patent/patent-core` 95 文件 / 1874 用例通过（含新增的提示词用例）。

## 查过但否掉的怀疑

`checkInventiveness` 在 `stepElements` 少于三步时直接判通过，初看像「配置错误也静默放过」。查规则库后发现是**有意分工**：创造性规则的步骤完整性由 `pathElements` 后置校验承担，规则集里只有 2 条用 `stepElements`，其余 28 条走 `pathElements`/`customCheck`。不成立，未记入发现。

## 观察（不构成发现）

`citation-ids.ts` 导出的 `PATENT_NUMBER_RE` 是带 `g` 的标志正则。当前仓库内没有任何 `.test()`/`.exec()` 消费者，`matchAll` 用法也不受 lastIndex 影响，所以今天没有缺陷；但把它作为公共 API 导出，未来若有人用 `.test()` 会得到交替结果。记在此处，供后续新增消费者时留意。

## 本轮无问题的重点区域

- `novelty/numeric-range.ts`：正负号并入数值 token、等长遮蔽避免重复提取、十进制换算的 ulp 容差、不可比对降级——边界处理完整。
