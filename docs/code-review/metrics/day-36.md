# Day 36 — 注入恢复与半成品检查

## 今日维度与范围

本日把 [day-35.md](day-35.md) 的 16 个两步场景按失败类型、恢复结果与副作用重新归并，检查首调失败前有没有写出半成品，以及失败结果能不能被机器区分。测量日与配置同 [day-32.md](day-32.md)。本日不改 `daily/`、业务代码、依赖、CI 或基础设施配置。

## 半成品检查

逐场景检查首调失败后的工作区：

- 附图：图号重复没有打开文件，也没有输出；两个缺失路径没有创建 SVG 或标注文件。标注文件只在二调成功后出现。
- 费用与期限：负数权项与非法日期都没有写出费用表或期限表；工具本身不落盘。
- 工作流与团队：缺 `name` 没有创建 `.patent-teams` 目录；缺 `caseId` 没有创建计划文档。二调各自创建一次，没有重复目录或重复计划。
- 文档交付：缺失文件与占位符都在登记前失败，没有新增交付记录。
- 法律：空文本与缺 `evidenceType` 都没有产生评估结果或规则命中。
- 视频：非法画幅没有创建项目；空 EDL 没有启动 ffmpeg，也没有留下 `out.mp4`；二调写出的 MP4 是 5150 字节。
- 知识：缺 `case_dir` 时日志文件不存在；二调追加 1 条，条目数从 0 变 1。空标题没有写出笔记文件；二调写出 30 字符笔记。

16 个场景没有留下半成品文件、空目录或部分写入的 JSON。

## 恢复质量

14 个场景在二调恢复了闭环，恢复后的结果与 [day-32.md](day-32.md)、[day-33.md](day-33.md) 的直接调用一致：费用合计 1330.00、期限 5 项、团队 id `p4-team-demo`、计划 `p4-flex-demo`、MP4 5150 字节、笔记 30 字符。失败没有把工具留在坏状态，也没有让二调读到首调的残留参数。

LGL-04 两次都是空库说明，不能算恢复，也不能算失败：空结果是该部署的有效状态。KNW-03 的首调是软跳过，二调成功；它不满足「首调失败」，在恢复统计里单列。

## 可解释性

10/15 个首调失败带 `name` 与 `code`：

- `PatentToolError`：`invalid_tool_input`、`file_not_found`。
- `ToolArgsError`：`INVALID_ARGS`，覆盖团队、计划、知识、法条证据与视频画幅。
- `LegalLawVerifyToolError`：`no_input`。
- `MediaFailure`：`MEDIA_EDL_INVALID`。

4 个首调失败只有文案：`patent_fees` 的负数权项、`patent_deadlines` 的非法日期、`document_deliver` 的缺失文件与残余占位符。它们都是预期工具失败，`tool/result.error` 为空；登记为 [F-CROSS-006](../05-findings.md#f-cross-006-patent_feespatent_deadlinesdocument_deliver-的预期失败仍抛普通-error失败事件没有-errorcode)，不在本批改代码。

KNW-03 的软跳过没有错误对象，`isError` 为假；记为 [OBS-010](../05-findings.md#观察列表)，等有调用方依赖 `isError` 统计时再处理。
