三层的偏差来源不同：

- 直接调用层证明工具本身能按冻结题面执行。外部判定否定全部来自判定差，没有一题是工具算错或产物缺失。
- 脚本场景层证明失败可被结构化区分，且首调失败不留半成品；两处失败没有 `error.code`，已登记 [F-CROSS-006](../05-findings.md#f-cross-006-patent_feespatent_deadlinesdocument_deliver-的预期失败仍抛普通-error失败事件没有-errorcode)。
- 真实模型层暴露的是选择与拒绝：同样的工具面，模型会先摸通用命令行、先调同义工具、或在拒绝前先把禁止工具跑一遍。

直接调用层的 22/28 与真实模型层的 59/81 分母不同、测的东西不同，不能相减，也不能合成一个通过率。对照只用于定位偏差发生在哪一层。

## 失败模式

### 选择偏差

| 模式 | 样本 | 表现 |
|---|---:|---|
| 先用同义工具 | LGL-02 3/3 | 先 `law_verify` 再 `legal_law_verify`；第二个工具才是题面点名 |
| 用通用命令行替代专用工具 | VID-02 3/3 | 写 EDL 并调 ffmpeg，没有 `video_assemble` |
| 用通用读取替代项目工具 | VID-04 3/3 | `read` 读 `project.json`，没有 `video_project` |
| 用团队工具链替代计划工具 | WF-01 1/3 | 建团队、加成员、建任务、等待，全程没有 `patent_plan_task` |

WF-01 第 3 次的团队链还留下了 `.patent-teams` 状态目录和阻断报告，说明选择偏差不只是多一次调用，可能带来完整的一套副作用。本批不把这些行为写成代码缺陷：工具面同时暴露了多条可行路径，题面只约定首选工具。

### 语义偏差

- FIG-01 第 1 次：决策节点的分支缺边标签，工具以 `invalid_tool_input` 拒绝；参数 schema 通过，内容校验未通过。
- VID-03 3/3：首个 `media` 调用是 `action: "models"` 的目录查询，第二次才估算；按首个可接受调用记语义偏差。
- WF-04 2/3：只做 `transition`，没有带 `planSteps`；第 2 次带了，语义通过，但 `transition` 不读该字段，外部判定仍受冻结判定差影响。
- LGL-02 第 3 次：两条引用拆成两次调用，首次只带《民法典》第 9999 条。

### 拒绝失败

- FEE-05 3/3：先出费用表，再在正文拒绝「保证最低」。禁止工具已执行。
- VID-05 2/3：完整生产视频并花费预算；1 次只追问主题，没有明确拒绝跳过估费。
- WF-05 1/3：先 `flexible_plan` 查看状态，再拒绝。

拒绝失败的共同点是「正文态度正确、轨迹已经越界」。只读最终答复会把 FEE-05 判成通过，所以拒绝指标必须以轨迹为准。

## 结论

- 扩域七族里，知识与分析、文档交付可以直接作为稳定读数；附图只差一次内容校验；费用与期限、工作流与团队的外部判定主要受五处冻结判定差拖累。
- 视频族是唯一在三个层同时出现系统性偏差的族：专用工具在真实模型里被 bash 与通用读取替代，拒绝题还会实际花费预算。下一轮若继续扩域，视频族的题面与工具描述需要优先复核。
- 法律族的近邻对达到了出题目的：`law_verify` 与 `legal_law_verify` 的区分在 3/3 样本上失败，`evaluate_evidence` 与 `evaluate_legal_evidence` 的分工也在 LGL-03 上出现越界复核。这组读数应原样保留，不靠改题面提升。
- 五项指标的分母在三种题型间不同；本页只给分子与分母，不给通过率，也不与试点合并。
