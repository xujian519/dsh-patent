# 无效宣告程序答辩

代表专利权人（被请求人）答复无效宣告请求，产出意见陈述书与（必要时）修改后的权利要求书。请求人侧（提出无效宣告请求、评估无效理由与成功率）用 patent-invalidity 技能。

## 必查清单（先查再分析）

- 先定答复期限，再据期限建提醒（两步）：①用 patent_deadlines 取本次答复期限——给出 patentType、filingDate、claimsPriority，把转送文件通知书放进 notices（`{kind: 'invalidation-transfer', dispatchDate: '…'}`），并传 invalidationRequestDate（提出无效宣告请求之日）；月数与起算口径由该工具按现行细则与指南给出，不要自行写死月数或口算，也不要因为材料里没写送达日就按申请日或其他日期估算——未记录送达记录时工具报待定，先补齐送达记录再谈期限。该期限是**指定期限，在无效宣告程序中不得延长**（专利法实施细则第 75 条），申请延期答复不成立；延期举证（审查指南第四部分第三章4.3.3）是期限内书面请求延期**提交某项证据**，不是延长答复期限，两者不得混用。②用 schedule_create 按返回的 dueDate 建两条提醒（到期前 15 天与到期日当天），口径与字段同 patent-oa-response 技能。
- 用 patent_workflow_run（manifestId=patent_invalidation_v1；input=无效宣告请求书正文，claims=权利要求书）跑解析与收口：grounds 阶段按无效理由表识别请求人实际援引的理由，claim-chart 阶段（mode=invalidity）把请求人的证据逐要素映射到权利要求；novelty 与 inventiveness 收口阶段同时读到理由与对照表。识别结果只表示请求书正文提到了该条款，不表示该理由已被实质论证，须按 `matched` 原文片段逐项核对。本预设的前台运行在审批门直接询问用户：放行即继续，拒绝则带结果名暂停（此时传入 approveStageIds 会被拒绝）；后台运行仍暂停，并以 approveStageIds 续跑。
- claim_chart_build（mode=invalidity）随图表给出的 invalidity_conclusion 是程序按行级映射算出的机械核验（逐权项单篇全覆盖、区别特征、从属权项法条路径、请求人证据的覆盖范围）。本件的主张不得与该核验相反；核验报出「仅附加特征被覆盖」时必须按该形态组织答辩，不得回避。
- 用 patent_case_search / patent_kg_query 取合议组对同类理由与证据形式缺陷（公开时间认定、外文译文、域外证据手续）的认定口径；条号与节号先经 `law_verify` 核验再引用——专利法实施细则第 70 条第 2 款（一事不再理）、第 72 条（转送请求书副本并指定期限陈述意见）、第 73 条（专利权人可修改权利要求书、不得扩大保护范围、不得修改说明书和附图）、第 75 条（指定期限不得延长），审查指南第四部分第一章2.5（听证原则）、第四部分第三章2.1 / 4.3.2 / 4.3.3 / 4.4.1 / 4.6.1 / 4.6.2 / 4.6.3、第四部分第八章2.2.1 / 4.3.3 / 5.1。随包索引的指南节已转录 2023 年修订版正文，逐字引用前用 `law_verify` 核验命题是否落在所引节及其子节内；第四部分第三章2.1、3.3 与第二部分第一章4.4 已被 2026 年版（2026-01-01 施行）修改，引这三节时以 2026 年版为准。
- 正式出件用官方标准表格：`render_patent_document`（template=invalidation-defense）渲染意见陈述书；载体系 `100902 复审、无效宣告程序意见陈述书`（陈述意见写 ⑥栏、附件列 ⑦栏，⑤栏勾选本次答复针对的通知书），⑥栏填写不下时用 `100014 附页` 续写，意见陈述书及其附件一式两份（审查指南第四部分第三章4.4.1）。口径源是模板的 `references/conventions.md`（§2 程序性意见、§3 修改、§4 逐项答辩、§5 质证、§6 反证登记、§10 载体），本技能不重述。

## 答辩流程

1. 先程序后实体：程序性意见单独成节，逐项给出主体资格与请求书形式、一事不再理（实施细则第 70 条第 2 款、审查指南第四部分第三章2.1）、延期举证的结论。程序异议成立时实体答辩无须展开；无异议时写明确的否定结论，不写己方的程序风险或应对预案。
2. 逐项理由各一节，覆盖请求书实际主张的每一项理由、每一项被主张的权利要求。请求书未主张的理由不得出现在本件，已主张的理由不得漏答。节标题由渲染器按草案结构生成（`5.1 权利要求 1、3 的创造性（专利法第 22 条第 3 款）`），起草时**不得手写**——手写会让答复件凭空多出一节，或漏掉一节。
3. 逐份质证请求人的证据，按真实性、合法性、关联性三项分别给出结论与依据：复印件未提交原件核对；外文证据未在举证期限内提交中文译文（审查指南第四部分第三章4.3.2、第四部分第八章2.2.1）；域外证据未办理规定的证明手续；互联网证据未记载发布时间且无其他凭证印证公开时间（第四部分第八章5.1）；以「本领域常规技术手段」主张公知常识而未提交证据（第四部分第八章4.3.3）。无异议的证据也写明「无异议」，不得省略。
4. 权利要求书的修改逐关通过：实施细则第 73 条（不得扩大原专利的保护范围、不得修改说明书和附图）→ 审查指南第四部分第三章4.6.1 的修改原则四项 → 4.6.2 的修改方式（权利要求的删除、技术方案的删除、权利要求的进一步限定、明显错误的修正）→ 4.6.3 的时机限制：**仅在**针对本无效宣告请求书、针对请求人增加的无效宣告理由或补充的证据、针对合议组引入的请求人未提及的理由或证据这三种情形的答复期限内，才可以以删除以外的方式修改权利要求书。不在这三种情形之一时只能作删除式修改，其余修改主张不得写入本件。未修改时写「本次答复未修改权利要求书」，修改对照表只登记一行「未修改」。
5. 反证在专利权人的举证期限内提交，并在该期限内对证据具体说明；技术词典、技术手册、教科书等公知常识性证据，以及用于完善证据法定形式的公证文书、原件等，可以在口头审理辩论终结前补充；外文证据的中文译文期限适用该举证期限（审查指南第四部分第三章4.3.2）。证据清单只登记反证（编号列写 `反证1`…），请求人的证据沿用请求书编号、在本件不重新登记。
6. 逐项答辩按请求人侧同一「四段式」组织——事实认定 / 证据分析 / 法条适用 / 结论，其中后两段由渲染器合并为一个「法条适用与结论」小标题与一段正文，因此每节只提交三段正文，节标题与这些小标题都由渲染器生成、起草时不得手写：事实认定段同时写明请求人在该理由下主张的事实与证据及其出处；证据分析段给出专利权人对该证据的意见，写「未公开」「无技术启示」必须指出对方证据的哪一处、以何理由不支持其主张，不得只作结论式陈述；法条适用与结论段回应请求人在该理由下主张的每一条权利要求。从属权利要求与其引用的权利要求同一路径——引用权利要求具备新颖性、创造性时，包含其全部技术特征的从属权利要求同样具备。
7. 逐权利要求结论表覆盖请求人主张的全部权利要求，不只独立权利要求；结论写请求维持有效／同意宣告无效／请求在修改后的权利要求基础上维持有效。

## 约束

禁止编造实验数据；禁止无逻辑链的空泛断言；凡引用法条／指南／判例须带来源（含 source_path），拿不出来源就删除该断言。本件是**对外提交件**：己方胜率、结论分档、风险评估与应对预案不进本件，写在 `invalidation-analysis` 件或案卷内部文件里；对请求人的证据只写实际提出的异议。

## 输出

意见陈述书 + 修改对照表（逐权项列修改前、修改后、修改依据）+ 逐权利要求结论。

## 质量门禁与人工确认

答辩策略、修改范围（是否修改、以何种方式修改）与是否提交反证先 ask_user_question 确认再起草；结论附免责声明；起草完成后用 rule_check（scope: 'patent-invalidation-defense'：与请求人侧同一作业，另加答复实践域，故逐点回应、禁止计数式论证、重复引证这类答复写作规则对答辩件同样评估）自检，命中逐条处置——改正文或在不采纳说明里写明理由——再经 patent-fact-check 与 patent-quality-gate。
