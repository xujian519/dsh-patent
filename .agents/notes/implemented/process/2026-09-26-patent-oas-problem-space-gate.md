# Agent Note: A problem-space DAG and a thresholded regression gate for the patent-oas gold benchmark

Status: implemented

English | [中文](2026-09-26-patent-oas-problem-space-gate.zh.md)

## Problem

[The 2026-08-26 note](../feature/2026-08-26-self-evolve-benchmark-output-scoring-patent-preset.md) shipped `patent-oas` as a runnable example benchmark: four gold cases, each pairing a public `statement` with a private `rubric`, scored 0–100 per case by an evaluator that sees only the private half. Two things were missing for it to act as a standard rather than a demo.

First, nothing held the gold standard still. A rubric could be relaxed, a case could be dropped, a statement could drift toward its own answer, and every gate in the repository would stay green — the benchmark's scores simply meant something different afterwards. Second, a case mean is a poor regression signal for patent practice: a drop of a few points says only that the deliverable got worse, not whether the practitioner lost the search step, the distinguishing-features step, the technical problem, the teaching argument, or the deliverable's form. The rubric text already carries that structure — each dimension names a facet and states its own point value — but nothing read it.

## Decision

**The benchmark's problem space is a directed acyclic graph, checked in beside the gold standard.** `examples/patent-oas/problem-space.yaml` declares 17 nodes, one per facet a deliverable is judged on, and `dependsOn` edges carrying the prerequisite structure: search precedes distinguishing-features identification, distinguishing features precede the actual technical problem, the technical problem precedes the teaching analysis, per-feature comparison precedes the equivalents analysis, and so on. The edges are the reason a node verdict is trustworthy: a node whose prerequisite failed is a node whose own score should not be read alone. Nodes exist only where a rubric dimension observes them; a prerequisite that no dimension scores (choosing the closest prior art) stays an edge rather than becoming a node with no observation surface.

**Every rubric dimension is mapped onto the node or nodes it observes, split by its own points.** The mapping is the single link between the two halves of the standard, and it is mechanical to check: for each dimension, the mapped weights must equal the points the rubric itself states; per case, the mapped weights must total 100; and every mapped weight must be positive, because a negative weight cancels a positive one into a sum that still looks right while the node scores it feeds are wrong, and a zero weight claims an observation surface that carries no weight. This is what turns "somebody edited a rubric" into a gate failure instead of a silent redefinition — a mapping that no longer adds up is caught whether the rubric changed or the mapping did.

**Thresholds are policy, and they are separate from measurement.** `examples/patent-oas/gate.yaml` holds three threshold levels. `node` is the per-facet floor and allowed regression; `case` and `aggregate` are the per-case and case-mean levels, and their `maxDrop` is deliberately tighter (3 against 5) because a case score is already an average of five dimension observations and a case mean is an average of four cases — those estimates carry less sampling noise, so they justify less tolerance. Without the case level a single case's uniform dip is diluted by the cross-case average behind each shared node; the spec pins that case with a run whose case verdict regresses while every node verdict passes. Two per-node overrides raise the floor on the spine nodes (`distinguishing-features`, `technical-problem`), because failing there propagates downstream.

**One keyless gate module owns integrity, thresholds, and the verdict.** `scripts/patent-oas-gate-core.ts` parses rubric dimensions, computes the gold digest, validates the DAG against the gold in both directions, validates thresholds and run records, derives case and node scores, and judges a run. `scripts/verify-patent-oas-gold.ts` is the CLI over it and runs in the `ciSharedStaticGates` aggregate beside `verify-self-evolve-eval`. Run records store only the raw per-dimension observations — `{ benchmarkId, recordedAt, provider?, modelId?, runsPerCase, cases: [{ caseId, dimensions: [{ index, label, points, score, scores? }], rounds?: [{ round, statementDigest?, dimensions: [{ index, score, scores? }], deliverableDigests }] }] }` — so case and node scores exist in exactly one computation and cannot drift as a second copy.

**The gold standard is pinned by content digest.** `gate.yaml` records `sha256` over every case's `statement` and `rubric`, plus each later round's review statement. Editing the gold standard is allowed and fails the gate until `--write` re-records the digest, which makes the intent explicit in the diff instead of accidental.

**Measurement capture is a separate, injectable runner.** `scripts/run-patent-oas.ts` (`pnpm run gate:patent-oas`) boots one `dsh --profile` process per call, the same shape the `self-evolve-eval` campaign runner uses; the orchestration lives in `scripts/patent-oas-run-core.ts` behind a `RunAgents` seam, and the CLI supplies the real spawn as that seam's implementation. Each run copies the agent state into that run's own directory, so the executor works in a private copy and the gold standard's `patent-state/` stays read-only; every round starts one executor that writes `deliverable.md` there, and every round starts one evaluator per rubric dimension that writes `score.json` in its own call directory, so an evaluator sees one dimension and never the whole rubric. A later round copies the previous round's working directory, keeps its deliverable as `previous-deliverable.md`, and removes the old `deliverable.md` and `agent.log`. The deliverable is capped before it is copied into that many prompts, `--dry-run` prints the plan and the per-case dimension counts without spending a call, and `--timeout-ms` and `--budget-ms` bound one call and the whole capture. The runner is not a gate leaf: it needs a key and skips without one, and the gate stays the thing that refuses a record disagreeing with the gold.

**An absent baseline fails the gate instead of reading green.** `--accept <record.json>` validates a run record, refuses to promote one that already fails its own floors, and otherwise copies it to `packages/self-evolve/evaluation/patent-oas-baseline.json`. While that file is absent the gate prints how to record one and exits 1: an exit code has to separate "nothing was compared" from "the comparison passed", so it does not follow the skip posture `scripts/verify-self-evolve-eval.ts` takes toward an absent decision record. `--run <record.json>` judges any recorded run against the same thresholds and attributes each failure to its problem-space node.

## Alternatives considered

**Judge the aggregate score alone.** Rejected: it is the signal the benchmark already produced, and it cannot say which part of patent practice moved. The user's requirement was attribution, not another number.

**Have the engine's evaluator return per-dimension scores.** Rejected: the evaluator prompt is model-visible and its output contract is the engine's public seam (`EvaluateCaseResult.score`, persisted in `ScoreboardEntry`). Splitting it would change a pre-stable public API, the evaluator's model-facing instructions, and the persisted scoreboard format to serve one repository gate. Storing the breakdown in the record and deriving the scores here keeps the engine untouched.

**Put the gate in a new package.** Rejected under the repository rule that an abstraction needs a current owner and need: there is exactly one consumer (this gate), and `scripts/` is where the repository's other verification gates live.

**Keep the flat case list and let the rubric carry the structure.** Rejected: the rubric states dimension weights but no relations, so nothing could distinguish "the technical problem was mis-stated" from "the conclusion was wrong but weighted less", and no gate could hold the two halves of the standard together.

**A test-only environment override for the baseline path, so a spec could drive the regression branch through the CLI.** Rejected: a hook that exists to make a test reachable is not configurability, and the regression branch is already pinned at the level where the decision is made (`evaluateRun`).

**Capture the deliverable from the runner's stdout.** Rejected: a one-shot `dsh --profile` run does not print the assistant text, so the reliable observation surfaces are a file the agent writes or the persisted session log. The artifact file keeps the runner independent of the persistence format and of frame decompression.

**Inline the work specification into the executor prompt.** Rejected: the engine hands the executor an agent-state *directory* and tells it to read the guidance there. Inlining the text deletes the file the executor is told to read, so the measured behavior differs from the engine's in a way no gate can observe. The runner copies the state per run instead.

**Grow the `self-evolve-eval` campaign runner into the shared harness for both.** Rejected: that scaffold is built around a dataset manifest and a paired pass/fail verdict per task, while a patent case is scored on a rubric scale and needs per-dimension observations; sharing the seam would have bent the manifest model and the verdict model into a shape neither needs.

## Consequences

- `pnpm run verify-patent-oas-gold` now fails on: a rubric dimension with no mapping or with a mapping that does not equal its points, a mapping onto an undeclared node or onto a node with no observation, a cycle in the prerequisite edges, a rubric whose points do not total 100, a stale or absent gold digest, a threshold outside its domain, a threshold override naming a node that does not exist, a baseline that cannot satisfy its own thresholds, a run record whose dimensions disagree with the gold, and — once a baseline exists — any node, case, or aggregate past its threshold.
- The regression comparison runs against one recorded keyed run: 2026-11-07 under the `headless` profile with `--provider deepseek-official --model deepseek-flash`, seven cases at three runs each, aggregate 96.43, checked in at `packages/self-evolve/evaluation/patent-oas-baseline.json`.
- The fixed `maxDrop` values are now a floor rather than the whole rule: [the 2026-11-07 note](2026-11-07-patent-oas-noise-aware-thresholds.md) raises the allowed drop to the measured noise where that is larger, because a repeat measurement of the same case moved by more than these thresholds.
- Verification: `scripts/patent-oas-gate.spec.ts` runs 63 cases and `scripts/patent-oas-run.spec.ts` 52, together covering a negative per rejection path, the CLI exit codes, the whole capture pipeline driven through a stub seam, and the real subprocess seam's timeout and non-zero-exit paths; the gate is wired into `ciSharedStaticGates` and therefore into `ci-primary`, `ci-static`, and `hygiene`, and the fork's `node-checks` lane — the one required check that carries this repository's static gates — runs `pnpm run verify-patent-oas-gold` directly, since no workflow invokes those aggregates.
- The case-level threshold exists because of a measured dilution effect, not by symmetry: the spec's case-level scenario fails at the case and passes at every node, which is the shape a node-only gate would have missed.
