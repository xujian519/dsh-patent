执行日期：2026-11-28。主维度：精简。

## 范围与口径差异

README 批次表记本批 60 个 `src` 文件；实测 `patent-core/src/atoms/` 树共 38 个：`atom.ts`、`handler.ts`、`tunables.ts`、`index.ts` 与 `handlers/builtin/` 下 34 个。README 的 60 与 `00-coverage.tsv` 的 batch 列不一致：台账把这 38 个文件标为 B3，而 [B3.md](B3.md) 的实际范围是 59 个文件，只含 `atoms/handlers/builtin/evidence-check.ts` 一个 atoms 文件。本批以 README 的批次定义为准，覆盖 atoms 全树；`evidence-check.ts` 已在 B3 精读并修复，本批只做结构层面的导出可达性分析，不重复审阅其行为。

## 审阅方法

- 结构扫描：全仓 `import`/`export` 反向解析统计每个内部导出的真实消费者；跨文件同名私有函数逐个比对函数体；同名重复常量值比对；`new Error(`、`catch`、`as unknown`、`any` 的静态清单；`callLlm` 全部调用点的取消信号透传核对。
- 高风险路径精读：`prior-art-filter.ts` 的 A24 宽限期基准、期内判定与公开日分流；`conflicting-application.ts` 的有效申请日与日期解析；`state-json.ts` 的读取契约；`llm.ts` 的统一调用骨架；`atoms/tunables.ts` 的配置读取与越界降级。
- 缺陷结论：上述路径未确认新缺陷。已核对的契约点：12 个 `callLlm` 调用全部透传 `signal`；`readStateJson` 把缺失、空值与非法 JSON 一律读作 `undefined`，是模块头声明的契约且调用方按缺失处理；`conflicting-application.ts:191` 的裸 `Error` 位于 `v8 ignore` 后的编程不变量分支。因此本批不新增 S-PAT 缺陷编号。

## 已排除的候选

| 候选 | 排除理由 |
|---|---|
| `readOfficeAction`、`readClaimsText`（adversary-model 与 adversary-review 各一份） | 两处虽是同名但声明了不同的返回类型（`AdversaryOfficeAction` 与 `AdversaryReviewOfficeAction`），函数体是把 `Record<string, unknown>` 收窄到可选字段记录的唯一位置；删掉需在各调用点补同样的类型收窄，不减少代码 |
| `domainGuidance`（claim-breadth 与 enablement-report） | 文案按 A26.4 概括范围与 A26.3 充分公开分别撰写，合并会让两条判定口径互相污染 |
| `readModelRecord`（claim-breadth 与 enablement-report） | 读取的字段集合与校验规则不同（前者校验项号与缺陷类型，后者校验实施方式与参数效果） |
| `DEFAULT_*` 键的同值常量（`reference_date`、`filing_date`、`priority_date`、`prior_art`） | 同值但属于不同 atom 的独立输入键默认值，合并会把互不相关的 handler 配置耦合到一起，违反「默认值由所属 handler 声明」的既有形态 |
| `state-json.ts` 吞掉非法 JSON | 模块头已声明「缺失、空值、非法一律读作 `undefined`，由 atom 决定缺失含义」，调用方按该契约处理，不是静默失败 |
