# Agent Note: upstream dsh-v0.2.1-alpha.5 sync

Status: implemented

English | [中文](2026-10-16-upstream-dsh-v0.2.1-alpha.5-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.2.1-alpha.4` tag to `dsh-v0.2.1-alpha.5`: 36 commits (25 non-merge), 586 files, +3,129/−1,117 lines, 23 files added, none deleted or renamed. The merge base is the alpha.4 release commit itself, which the previous sync landed as a merge commit, so one `git merge` reaches the tag and no upstream commit is re-derived. `git merge-tree` predicted 4 conflicting files and the merge produced exactly 4, the smallest conflict set of any sync so far.

The release's own subject matter is desktop, web, and account settings. The Windows packaging runner moves under Task Scheduler supervision; publishing gains a `preflight-desktop-publish` / `desktop-publish-qualification` script pair with retained-artifact and COS-denial goldens; Windows packaging defaults to signed; and the account settings plugin gains a stacked notice surface (`notice-transition.ts`, plus the `v0.2.1-alpha.4/account-notification-fields` upgrade guide). Web gains a provider-aware model label slot, per-session terminal discovery, a slash-menu refresh after a plugin change, and a sidebar clip fix. Vendor gains a staged `cordis-rc11-upgrade-plan.md`.

One upstream line of work reaches the fork. Two release commits reworked how the PTC instructions are composed so that no call site depends on shared prose, then restored the model-visible wording to the text the released SDK persona is compatible with. Together they rewrite `packages/core/tool-executor-ptc/src/ptc.ts`, `ts-types.ts`, and `py-types.ts`, and the restored wording also reaches `packages/fs/tool-fs/src/read.ts`, `packages/subagent/tool-subagent/src/index.ts`, the tool catalog, and every session and SDK snapshot that carries a system prompt.

## Decision

- **The sync branch merge-forwards the release tag.** `sync/upstream-dsh-v0.2.1-alpha.5` carries the merge and the PR lands it as a merge commit whose first parent is the fork's `master`. A squash would remove upstream's commits from the fork's graph and push the next sync's merge base back to this tag.
- **Conflicts are resolved by class, never by line range.**

  | File | Resolution |
  |---|---|
  | `packages/core/tool-executor-ptc/src/ptc.ts` | The fork's run-code flavor extraction is kept; the release's delta is ported into it |
  | `packages/lsp/tool-lsp/package.json` | The fork's manifest, with the version raised to `0.2.1-alpha.5` |
  | `docs/tool-catalog.i18n.yaml` | Generated sidecar; re-recorded by the generator |
  | `snapshots/session/ptc-python-turn/tool-schemas.expected.json` | Re-recorded by fork replay; copied from neither side |

- **The release's PTC delta lands in `run-code-flavor.ts`, not in `ptc.ts`.** The fork keeps a language's `run_code` description and its `code` parameter description together in `packages/core/tool-executor-ptc/src/ptc.ts`, which upstream does not have. Upstream's two commits carry four changes. `runCodeFlavor` gains an `execution` override for the program-format wording; a `TYPESCRIPT_FUNCTION_FLAVOR` describes a runtime whose `programFormat` is `function-body`; `resolveFlavor` branches to it on `runtime.language === 'typescript' && runtime.programFormat === 'function-body'`; and the parameter order moves `code` before `description` in both the static `parameters` block and the dynamic getter, with the jsdoc and the removed "Provide `description` before `code`" sentence of `RUN_CODE_DESCRIPTION_PARAM_DESCRIPTION` following. The first three are flavor-module concerns and were ported into `run-code-flavor.ts`; the fourth is a `ptc.ts` concern and auto-merged.
- **The release deliberately changes model-visible prompt text, and the re-recorded goldens carry the release's text.** The restoring commit moves the wording back to what the released SDK persona is compatible with, so the merged tree emits the *shorter* sentences where the fork's pre-merge tree emitted longer ones: `read` loses "or sed, head, or tail" and gains "to continue reading large files", and the subagent section drops its "end your turn instead of sleeping or polling" clause. Both sentences' sources moved with them. A re-recorded golden that disagrees with the release here is a build artifact, not a fork divergence.
- **The version is pinned across the fork's own surface.** The root manifest, 47 fork-only manifests, and `SIDEBAR_SERVICE_VERSION` in the since-removed better-sidebar package's `service.ts` move to `0.2.1-alpha.5`. `pnpm exec tsx scripts/release/verify.ts --family dsh` resolves 388 family members at that version with no unordered peer declaration, and `pnpm install --lockfile-only` reports "Already up to date" without touching `pnpm-lock.yaml`.
- **The tool catalog pairing is re-recorded rather than side-taken.** `docs/tool-catalog.i18n.yaml` is generated from the catalog's paired pages; the generator rewrote `docs/tool-catalog.md`, `docs/tool-catalog.zh.md`, `docs/config-catalog.md`, `docs/config-catalog.zh.md`, and `apps/cli/composition.md` in the same pass, and `verify-translation-pairing --write` re-recorded the sidecar.
- **Snapshots are split by who owned the change.** Upstream changed 97 snapshot files (13 SDK, 77 session, 7 web) and all 97 are in the merge. Eighteen of them changed on both sides — the PTC prompt family plus `snapshots/sdk/sdk.snapshot.ts` — and were re-recorded by replaying the fork's tree rather than by taking either side. Nine `snapshots/acp/*/stdout.expected.jsonl` re-pin `agentInfo.version` to `0.2.1-alpha.5`, the only drift the ACP replay reported. The web lane needed no re-record: its 7 changed files are upstream's, and all five `apps/web/tests/*.snapshot.ts` drivers pass unchanged.
- **`pnpm run build:artifacts` runs before any `DSH_SNAPSHOT=refresh`.** The snapshot harness spawns the real profile runtime, which resolves workspace packages to their built `lib/`, so a `lib/` older than the merged `src` silently poisons every refreshed golden. This is the trap that cost the most time in this sync and is recorded under Consequences.

## Consequences

The fork ships upstream's v0.2.1-alpha.5 baseline with its patent, self-evolve, desktop, better-sidebar, and document surfaces intact, and the conflict count fell from 38 to 4 — the rename of the fork's plugin catalog in the previous sync removed the add/add collisions that dominated it.

The lesson this release adds is that a source-plane gate and an artifact-plane gate can disagree while both report success. `pnpm run typecheck` reads `src` through tsconfig `paths` and passed on the merged tree; `DSH_SNAPSHOT=refresh` read the stale `lib/` left behind by the pre-merge build, so the first refresh pass over `snapshots/sdk` wrote 11 `system-prompt.expected.md` goldens carrying the fork's pre-merge wording and exited successfully. Nothing in the merge's or the refresh's exit status separated that from a correct recording. What identified it was a four-ref comparison of one sentence across the merge base, `master`, the release tag, and `HEAD`: the merge base and `master` carry the long form, the tag and `HEAD` the short form, and the freshly written goldens carried the long form, which belongs to a tree that is no longer checked out. `git checkout -- snapshots/sdk`, `pnpm run build:artifacts`, and a second refresh produced goldens that match the tag.

The reason the wrong text looked plausible is the shape of that restoring commit: a release commit whose subject is "restore compatible PTC guidance and SDK persona" moves model-visible text *backwards*, toward the wording an earlier release shipped. A conflict here cannot be resolved by preferring whichever side looks newer, and the re-recorded goldens are the only evidence of which side the merged tree actually emits.

Three divergences still need attention at each release, unchanged: the fork's presets are the merge's landing place for upstream's composition changes, the archived-note seals must match upstream's for the notes it retires, and the fork's notes must track upstream's workflow paths into `workflows-disabled/`. The release's new pwsh parse step in `.github/workflows/ci.yml` reached the fork's archived copy at `.github/workflows-disabled/ci.yml` through rename detection, so the fork's disabled workflow is current with the release's without a manual port.

## Alternatives considered

- **Keeping the release's `ptc.ts` whole and dropping the fork's flavor extraction.** Rejected: the extraction is what keeps a language's two model-facing strings in one place, and reverting it would re-derive the same conflict at every later release.
- **Collapsing the flavor module back into `ptc.ts` to match upstream's layout.** Rejected for the same reason, and it would also have to re-absorb the release's function-body flavor into a file the release itself keeps free of per-language text.
- **Taking the release's `packages/lsp/tool-lsp/package.json`.** Rejected: the fork's manifest lists `@deepseek-ai/dsh-value` and the fork's own `dsh-timeout-guard` rename of the tool-call timeout package, neither of which the release's manifest names. The fork's side differs from the release's by exactly those two dependency entries, the description's character encoding, and the version.
- **Re-recording the PTC prompt snapshots before rebuilding the workspace.** Rejected after the fact: that is the pass that produced the 11 poisoned goldens described under Consequences. The usable order is build, then refresh.
- **Taking the release's `docs/tool-catalog.i18n.yaml` and re-recording only if a gate failed.** Rejected: the fork's catalog carries rows the release's does not, so the sidecar's per-heading hashes belong to neither side's file; the generator plus `--write` is the only correct producer.

## Testing

`pnpm run typecheck` passes all five gates — Host Typert, the host and client compilers, and both aggregates — on the merged tree, which is what proves the release's PTC changes and the fork's flavor module agree.

`pnpm run lint` exits 0 with the one pre-existing unused-disable warning in `packages/experimental/client-ui-cot-translation/src/index.ts`. `pnpm run hygiene` reports 22 of 22 gates passing, which is what confirms the fork's `dsh-timeout-guard` rename of the tool-call timeout package leaves no dangling reference to the release's name.

`pnpm run doc-sync` reports 50 of 51. The one failure is `verify-repository-references`, the same one the previous sync reported. The gate matches runs of seven to forty hexadecimal characters against the local object database and treats a unique prefix of a commit as a maintained commit reference. A pillow wheel's byte size in `python/sdk/uv.lock` coincides with such a prefix, and the alpha.3 and alpha.4 sync notes are flagged for quoting that size while recording this same failure. The gate's own contract states that an object absent from a shallow history cannot match, so CI's shallow clone cannot report these lines, and `git diff --stat master HEAD` shows the flagged files untouched by this merge. This note therefore names the release's commits by subject rather than by hash.

`pnpm run build:artifacts` and then `pnpm run build:check` pass, which is the pair that puts the merged `src` into `lib/` before the snapshot refresh described above.

`pnpm run test:snapshot` replays 223 keyless cases across the session, sdk, acp, and web lanes with 2 skipped and no failures, in 4 test files. The five `apps/web/tests/*.snapshot.ts` drivers pass 15 of 15.

`pnpm run test:coverage` writes no `ERROR: Coverage` line, which is that gate's own pass condition for the per-file 100% bar, and passes 52,667 of 52,894 cases. Seven cases fail, none on a path this merge touches. Five are whole-repository or real-watcher scans that exhaust their budget under the full lane's load (`scripts/report-structure.spec.ts`, `scripts/persistence-schema.spec.ts`, `scripts/verify-suppression-reasons.spec.ts`, `packages/boot/hmr/tests/watch-config.spec.ts`, `packages/api/workspace-files/tests/changes.spec.ts`); re-run alone, all five pass, including the fork's `_closers`-based arming loop in `watch-config.spec.ts` that the earlier syncs added. One is the `NoDefaultCurrentDirectoryInExePath` variable this shell exports, which makes `packages/subprocess/subprocess-local/tests/spawn-runner.spec.ts` read a Windows `PATH` without its leading entries: under `env -u NoDefaultCurrentDirectoryInExePath` its 35 cases pass. The seventh is `packages/patent/patent-tools/tests/figure-freecad-real-render.spec.ts`, which drives this machine's FreeCAD through a synchronous spawn; the probe never returns, so the case's own timeout cannot interrupt it, and it held the lane for seventeen minutes until the process was killed. CI installs no FreeCAD and skips that suite.

`pnpm run verify-test-skips` records darwin at 52,894 cases and 219 skipped, from the `pnpm test` run that also produced the coverage figures. The commit that recorded the release's platform-gated cases had already moved linux to 52,836 and 222 but left darwin on its alpha.4 figures, and the platform's budget is recorded from a local run by the convention the earlier budget commits followed. The two platforms' skip counts remain three apart, as they were before the release.
