# 权利要求书与说明书 — 版式惯例（Conventions）

> 生成或修改本模板前必读。与 `checklist.md` 配套。

## 1. 文书结构（固定顺序）

1. 页眉（所名 + 密级；正式提交版可删除）
2. 文书抬头（类型徽标 / 标题 / 案卷号）
3. 案件信息表（发明名称 / 申请人 / 发明人 / 代理人 / 撰写日期）
4. 权利要求书
5. 说明书
   - 技术领域
   - 背景技术
   - 发明内容
   - 附图说明
   - 具体实施方式
6. 摘要
7. 落款 + 免责声明 + 页脚（正式提交版可删除）

## 2. 权利要求书规范

- 独立权利要求采用「一种……，其特征在于，……」格式。
- 从属权利要求引用用「如权利要求 X 所述的……，其特征在于，……」。
- 权利要求编号连续，一项一段，首行缩进对齐编号。
- 权利要求中不得出现「大约」「基本上」「优选」等模糊词，除非确有技术必要性。
- 功能性限定需得到说明书实施例支持。

## 3. 说明书五部分

- **技术领域**：写明所属技术领域和具体主题。
- **背景技术**：客观描述现有技术缺陷，不贬低他人专利。
- **发明内容**：明确要解决的技术问题、技术方案、有益效果。
- **附图说明**：按图号逐一说明；列表项只写图名与描述文字，图号（「图N为」）与句末标点由渲染器生成。
- **具体实施方式**：至少一个完整实施例，结合附图标记说明。

## 4. 摘要规范

- 不超过 300 字。
- 写明发明名称、技术方案要点、主要用途。
- 不得含商业性宣传用语。

## 5. 内部审稿版 vs 正式提交版

| 元素 | 内部审稿版 | 正式提交版 |
|---|---|---|
| 页眉密级 | 保留 | 删除 |
| 免责声明 | 保留 | 删除 |
| 落款签名 | 保留（内部审核用） | 删除 |
| 页脚 | 保留 | 删除 |

切换方式：覆盖 `--sati-doc-confidential` 为空字符串，并移除 `.disclaimer`、`.doc-footer`、`.signature` 区块。

## 6. 视觉与版式纪律

- 沿用 `assets/templates/patent/tokens.css` 品牌变量；agent 不改样式。
- 权利要求项避免跨页断裂（`page-break-inside: avoid` 已内置）。
- 表格数字列使用 `tabular-nums`。

## 7. 说明书段落编号（可选体例）

《专利法》《专利法实施细则》与《专利审查指南》均未要求说明书写段落编号，也没有条款提到该体例；是否编号取决于提交体例。模板默认**不声明**，渲染件因此不带段落编号。

- **需要时自行声明**：在说明书节的 `<section>` 上加 `data-paragraph-numbering="[0001]"`，`render_patent_document` 会在注入内容之后给本节每个 `<p>`／`<li>` 逐段写入编号。属性值即编号形态（`[0001]` 表示方括号、四位、左补零）。
- **编号范围**：只对声明所在容器生效。权利要求书、摘要、说明书附图不编号——权利要求用 `1.` `2.` 序号，摘要是一段连续文字。
- **编号单位**：一个 `<p>` 或一个 `<li>` 就是一段，按文档顺序从 `[0001]` 连续。`h1`–`h6` 小标题、表格内容、只有图片的段落都不编号，也不占序号。
- **不要手写编号**：引擎会剥掉既有编号并按实际段落顺序重写，手写的编号不生效，增删段落时反而容易留下错号。
- **改了段落就要重渲**：插段、删段、调整顺序之后必须重新渲染；编号是在渲染时按当时的内容生成的，手工改渲染结果会让编号与段落对不上。

## 8. 表格纪律

- 表格**仅允许出现在具体实施方式**：技术领域、背景技术、发明内容、附图说明四部分不得含表格（草案校验会拒绝）。
- 每个表格必须**命名**：草案里给 `name`（如「附图标记说明」），渲染器自动生成「表 N · 名称」表题并按文档顺序连续编号；`name` 不得以「表+数字」开头（不自编号）。
- 表头至少一列，数据行至少一行，行宽与表头一致，单元格非空。
- 附图标记说明表是常见用法：列「标记 / 名称」，作为具体实施方式中的命名表格出现，不再另设「附图标记说明」标题。

## 9. 品牌契约注入点

同 `assets/templates/patent/DOCS.md` 与 `tokens.css`。抬头所名、密级由 CSS 变量注入。
