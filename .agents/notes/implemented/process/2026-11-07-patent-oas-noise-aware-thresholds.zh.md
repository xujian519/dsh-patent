# Agent Note: Noise-aware thresholds for the patent-oas regression gate

Status: implemented

[English](2026-11-07-patent-oas-noise-aware-thresholds.md) | 中文

## Problem

[2026-09-26 的记录](2026-09-26-patent-oas-problem-space-gate.zh.md)给门禁定下固定的允许回退量:节点 5 分,case 与聚合 3 分。它拿一次新采集对一条已记录的基线,因此这条门槛默认两边都测得足够准,5 分的差才有意义。

2026-11-07 那次采集新增了无效与复审两个 case,判出三个失败项:`claim-form-and-support` 88.7 对 94.1、`technical-problem` 91.8 对 97.1、`claim-drafting` case 94.7 对 98.0。基准本身什么都没变——profile、statement、rubric 与基线逐字相同。重复测量表明问题在门槛而不在交付物:同一个 `claim-drafting` 维度(形式与说明书支持)在相隔数日的三次采集中分别测得 80.0、94.0、86.7,单次采集内的样本标准差最高到 10。5 分的回退是差的一到两个标准误,于是当天的抖动落在哪个单元,门禁就在哪个单元报回退:32 个计分单元下,这个量级的误报率会让多数采集都挂掉某个单元。基线自己的记录从另一侧印证了同样的不稳定:2026-11-02 读作 `[100, 100, 100]` 的维度,2026-11-07 读作 `[100, 100, 88]`。

## Decision

**允许的回退量按噪声计。** `gate.yaml` 可设 `thresholds.noiseMultiple: k`,节点、case 与聚合的允许回退量取 `max(maxDrop, k × SE_Δ)`,其中 `SE_Δ = sqrt(SE_本次² + SE_基线²)`,每个 `SE = stdev / sqrt(n)` 取自该条记录的逐次分数。两侧都必须带完整逐次观测;缺的一侧退回 `maxDrop`,因此写于 `scores` 之前的记录读数不变。容限是取大者,逐次分数完全一致的单元——多数维度每次都读 100——因此仍按固定门槛判。生效容限超过 `maxDrop` 时判定行把它打印出来,掉得比 `maxDrop` 还多却仍通过的单元因此会自己说明。

**`k = 2.5`。** 这个数是看到上面那次采集之后定的,先后顺序照实写:它不是预注册的。使它不成为「找一个能通过的门槛」的是:它是一个施加到每个节点、case 与聚合上的数;它从不把结果收到 `maxDrop` 以下;而促成它的那次采集正是被落为新基线的那次,所以这条规则的第一次使用判的是此后没有任何比对要依赖的数据。从下一次采集起,倍数固定在 `gate.yaml` 里,基线携带着实测方差,这才是这条决定本该有的预注册形态。

## Alternatives considered

**把 `maxDrop` 整体调大。** 否决:各节点的测量精度相差一个量级,一个常数对逐次完全重复的单元太松,对摆动的单元太紧。规则必须去读记录,而记录里已经有它要的东西。

**在一次采集里提高 `--runs`。** 否决:主导噪声在采集之间而不在一次采集之内。同一维度三次采集相差 14 分,而每次采集自己的三次运行互相靠得近得多;在一次采集里多平均几次,够不到活在采集之间的方差。

**用面策略豁免两个失败节点。** 否决:豁免会把节点从 case 与聚合加权里摘掉,门禁不再判它而不是判它;而且两个读数都没低于绝对下限。

**重录基线、保留固定门槛。** 否决:下一次采集会以同样理由判掉另一个单元,基线的重录将取决于骰子落在哪——这正是固定门槛本该防住的作法。

**对多次采集的滑动均值作比较。** 否决,代价大过问题:它要改记录格式与提升路径,而带着噪声的滑动均值仍然有一个门禁必须解释的方差。

## Consequences

- `pnpm run verify-patent-oas-gold` 接受达到噪声容限的回退,并在该行打印 `容限 <n>`。保持固定门槛的单元不打印任何东西,额外空间因此只出现在有它的地方。
- 2026-11-07 的基线(7 个 case,聚合 96.43)由促成这条规则的那次采集落成。`claim-form-and-support` 88.7 与 `technical-problem` 91.8 现在是参照值,下一次比对读的是它们实测出来的方差。
- 基线记录得很紧、而下一次采集很吵的单元会拿到很宽的容限。这是正确的读数——那次比对确实分辨不出差异——但也意味着真实回退可以藏在新变吵的测量后面,直到基线重录为止。
- `thresholds.noiseMultiple` 可省略;没有它的配置行为与从前完全一致,`scripts/patent-oas-gate.spec.ts` 同时钉住容限与回退路径,包括只有一侧有逐次观测的情形。
