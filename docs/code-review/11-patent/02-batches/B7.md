## 采纳并修复（11 条）

**P1（6 条）**

- **F-PAT-105** 判例检索不按文档类型收窄：`documents` 表同时存法条/指南/笔记，SQL 却不加 `doc_type` 过滤。真库上搜「假冒专利的」前五条有 4 条是 `law_article`，模型会把法条当在先判例引用。三条热路径 SQL 与动态过滤统一加 `d.doc_type IN ('case','judgment')`，`count()` 同步收窄。
- **F-PAT-106** `node_type` 别名把语料真实类型映射掉：真库类型就叫 `Judgment`(6,831) / `LawArticle`(3,500)，别名表却把它们映射成四个不存在的类型且不带回原名，按类型浏览恒为 0。改为「原名 + 历史别名」。
- **F-PAT-109** 引用门把「本索引不管的法律」判成核验失败：索引只载民法典与民诉法，抽取器却无条件识别劳动合同法、公司法，导致合法引用被拒且文案劝模型删掉正确引用。索引补齐四部常引法，未覆盖的法律跳过而非判失败。
- **F-PAT-110** 显式 `manifestPath` 失效时静默退化为 base 包：路径拼错后规则数从 125 条降到 6 条，门禁「仍在跑」只有一行 warn。改为加载期抛错，仅未配置才走默认。
- **F-PAT-111** 移除成员把已取消/失败的任务复活成 pending：requeue 循环只跳过 `completed`，对终态任务调用 `invalidateTaskAttempt` 把状态改回 `pending` 并删产出，随即被重新派发。改为终态任务只保留。
- **F-PAT-112** 审批门缺 handler 时被 executor 文本顶替：`assertKnownAtoms` 只校验 atom 契约，handler 查不到时一段文本就成了「门已放行」，事件仍带 `atom:'approval-gate'` 且 `completed:true`。改为审批门必须注册 handler；收口重放显式传 `atomStagesMayUseExecutor: true`。

**P2（5 条）**

- **F-PAT-107** 知识库安装先提交再破坏性裁剪：紧凑副本先 rename 到输出，之后才建列、压缩、删表、二次 VACUUM；失败留下半裁剪库且旧库已覆盖（最坏是 `search_prefix` 全 NULL）。全部裁剪改到临时副本，成功后才提交。
- **F-PAT-108** KG 引用关系词表漏掉语料里最多的两类边：`CITES_EVIDENCE`(74,151) 与 `APPLIES_LAW`(54,012) 未收录，约 12.8 万条引用链静默缺失。补齐并让工具侧引用同一常量。
- **F-PAT-113** 结构化缺口重试耗尽被记成完成：文本信号耗尽标 degraded，结构化信号耗尽却直接记成功，缺口报告进了产出但运行报 `completed:true`。改为同样标降级并加 `[WORKFLOW_REVISION_EXHAUSTED]` 前缀。
- **F-PAT-114** 引擎 JSON 数组里的 `null` 元素让整次元数据调用失败：`parseJsonArray('[null]')` 后取属性抛 `TypeError`。原登记为 F-PAT-055，本轮复现并关闭。
- **F-PAT-115** ego-browser 环境白名单在真实 subprocess 上不生效：`spec.env` 合并到 `scrubbedParentEnv()` 之上，省略不等于移除，而该擦除只认 `KEY|PASSWORD|SECRET|TOKEN`；`GH_PAT`/`SSH_AUTH_SOCK`/`AWS_PROFILE` 会进入第三方浏览器进程。改为对非白名单名字写 `undefined` 墓碑。原登记为 F-PAT-016，其修复此前只改了断言层，本轮关闭。
