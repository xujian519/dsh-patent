# 优先级规则

## 排序公式

优先级 = 风险严重度 × 触发可能性 × 修复紧迫性。

| 因子 | 取值 | 分值 |
|---|---|---|
| 风险严重度 | Blocker / High / Medium / Low | 4 / 3 / 2 / 1 |
| 触发可能性 | 高 / 中 / 低 | 3 / 2 / 1 |
| 修复紧迫性 | 立即 / 本周期 / 可延后 | 3 / 2 / 1 |

总分 36—12 为 P0，11—6 为 P1，5—3 为 P2，2—1 为 P3。分数只用于排序，不替代严重度判定；Blocker 无论分数都进入 P0。

## 队列

| 队列 | 含义 | 处理方式 |
|---|---|---|
| P0 | 立即处理 | 上报仓库负责人，暂停相关改动，先补证据与最小复现 |
| P1 | 本周期内处理 | 进入修复批次，补测试后修复 |
| P2 | 下一周期内处理 | 进入常规清理队列 |
| P3 | 可延后 | 记录并观察，重复出现时升级 |

## 根因型问题

满足以下任一条件的条目按“根因型”处理：

- 同一根因在三个及以上位置出现。
- 同一类缺陷在多个域重复出现。
- 修复一个点无法阻止同类问题再次出现。

根因型条目单独建 ID，子条目用“由 F-XXX-NNN 派生”标注；优先级按受影响面的最大值计算，并在 [07-ci-hardening.md](07-ci-hardening.md) 提出持续防线。
