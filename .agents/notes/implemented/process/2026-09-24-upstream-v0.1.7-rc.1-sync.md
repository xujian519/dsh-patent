# Agent Note: upstream v0.1.7-rc.1 sync

Status: implemented

English | [中文](2026-09-24-upstream-v0.1.7-rc.1-sync.zh.md)

## Problem

The fork moved from upstream's `dsh-v0.1.7-alpha.2` tag, this merge's base, to the `dsh-v0.1.7-rc.1` release. Upstream advanced 156 commits across 933 files (+13851/−3101) while the fork carried 656 of its own across 3555 files, and the merge conflicted in 24 paths: 15 of them the Chinese page, the pairing record, or the English page of the `apps/desktop` README and five generated catalogs, plus `pnpm-lock.yaml`.

Four upstream changes judge content the fork authors. The desktop work rewrites `apps/desktop/src/main.ts`'s host startup, protocol registration, and menu construction, and stages a native engine beside the update archive. `apps/cli/src/plugin.ts` gains the profile version-exemption command beside the fork's pnpm failure hints. `packages/boot/app-boot/src/profile.ts`, auto-merged into the fork's copy, admits a profile bundle only while its own dsh peers resolve or the profile exempts that exact pair. Two client packages narrow what a conversation node hands to a seat callback, and the session-event fold now reads `SessionEventLike`.

## Decision

- **The version family aligns inside the merge commit, and `constraints` enforces the alignment.** Root and all 352 members move to `0.1.7-rc.1`, and the 43 manifests the fork alone ships are still on `0.1.7-alpha.2` until this commit moves them: `check-workspace-constraints` reads every manifest in the tree and requires each version to equal the root's, so a fork-only manifest left behind fails the gate that upstream's own manifests pass. The single version mirror, `SIDEBAR_SERVICE_VERSION` in the since-removed better-sidebar package's `service.ts`, moves with them, and `pnpm install --lockfile-only` on the merged manifests leaves `pnpm-lock.yaml` unchanged.
- **The ACP corpus's pinned handshake version moves with the release.** Nine `snapshots/acp/*/stdout.expected.jsonl` files record the handshake's `agentInfo.version`, which `packages/acp/acp/src/index.ts` derives from its own manifest, so every release breaks the cases holding that expectation. Each moves to `0.1.7-rc.1`, and the keyless replay of `snapshots/acp` passes its 16 cases. The hand-maintained pin and the placeholder scheme that would retire it are recorded in `docs/TECH_DEBT.md`.
- **The client conflicts take upstream's relaxed identifier vocabulary with the fork's branding intact.** `packages/client/ui-agent-preset/src/client/section-store.ts` drops its local `message()` helper for `errorMessage` from `dsh-value` at all three call sites. `packages/client/ui-tool/src/client/tool/ToolCallTree.tsx` keeps the `ToolCallId` cast that carries the chat node's string id into the seat callback speaking the host's branded vocabulary. `packages/client/ui-patent-teams/src/client/teams-model.ts`, which no conflict marked, widens its fold parameters to `SessionEventLike` and drops its unused `SessionEvent` import.
- **`plugin.ts` keeps the fork's pnpm failure hints and adopts upstream's exemption command.** `setProfileVersionExemption` and the `dsh plugin --profile … allow-version … --accept-risk` line arrive from upstream; the fork's stderr accumulation and its two failure classes survive, and the git-hosted hint keeps naming `pnpm.onlyBuiltDependencies` in the profile's `package.json`, where pnpm 10 enforces that allowlist on this host while its own output points at `pnpm-workspace.yaml`.
- **The desktop conflicts keep the fork's startup sequence and take upstream's engine packaging.** `apps/desktop/src/main.ts` and its startup spec resolve as the union: upstream's host inspect port, protocol registration, and menu refactor land inside the fork's `onFailure`/`backend.start` sequence and its Windows-only devtools menu items, and both suites' cases stay. `apps/desktop/tests/installed-update-package-content.spec.ts` takes upstream's fixture, which stages the LibreOffice engine beside the archive and adds its `soffice.exe` to the resigned executables.
- **The README and the five generated catalogs resolve as the union of both parents.** `apps/desktop/README.md` keeps the fork's product sections and upstream's rewritten ownership, engine, and development prose, with the Chinese page and the pairing record following. `docs/capability-seams`, `docs/config-catalog`, `docs/event-producer-consumer`, `docs/module-graph`, and `docs/tool-catalog` come from their generators on the resolved tree, and each edited pair re-records its blob hashes through `pnpm run verify-translation-pairing --write`.
- **`packages/bundle/web-app/package.json` keeps the fork's presets beside upstream's added client packages.** The fork's `patent` and `document` presets, their pages, and the `skills` directory stay in `files` and `exports` with the packages that render them, and upstream's new dependency entries arrive alongside.
- **`profile.spec.ts` carries upstream's bundle-compatibility case and the fork's pin suite.** Upstream's case skips a bundle whose own dsh peers are incompatible until the profile exempts that exact pair; the fork's `ensureProfileVersionPins` cases stay. Both parents added cases at the same point of the file, so the union is the resolution rather than a chosen side.
- **Version strings that are records or fixtures stay on `0.1.7-alpha.2`.** `docs/TECH_DEBT.md`, `.agents/audits/2026-09-23-snapshot-lane-and-loader-issues.md`, the alpha.2 sync note triplet, `apps/desktop/tests/desktop-build-version.spec.ts`, and `packages/boot/app-boot/tests/plugin-compatibility.spec.ts` state that release as history or as a value their case needs to differ from the shipped one.
- **The fork's vendor-rescope whitelist gains the one file this release adds that trips it.** `packages/extensions/ui-cordis/src/client/CordisPreparingRow.tsx` spells `PropsLocale<'cordis'>`, and that `'cordis'` is the UI locale namespace the package's `locales.ts` exports as `NS`, not a package name, so `GENERIC_SKIPS` exempts it the way it already exempts the four sibling row files. Upstream's own `scripts/rescope-vendor.ts` lacks the entry and its CI does not run that gate, so only the fork's `hygiene` reports the residue.

## Consequences

The fork ships upstream's v0.1.7-rc.1 baseline with its patent, document, desktop, better-sidebar, synapse, self-evolve, and plugin-market surfaces intact. The 43 manifests upstream does not ship are the set each sync bumps by hand, and `pnpm run constraints` is what makes forgetting one impossible. The generated catalogs and the desktop README are the files where both parents replaced the same prose, so a later sync reads those conflicts as a union again. The ACP handshake pin keeps costing a nine-file refresh per release until the placeholder scheme lands, and `docs/TECH_DEBT.md` remains a fork-only ledger whose quoted paths `verify-package-paths` reads as references — its line for the deleted `client/connection/src/client/fixture.ts` is the one gate failure this tree carries.

## Alternatives considered

- **Bump only upstream's manifests and leave the fork's 43 at `0.1.7-alpha.2`.** Not available: `constraints` compares every manifest against the root version in one pass, and `scripts/release/verify.ts` resolves all 352 as one family, so a partial bump fails both readings.
- **Take upstream's `allowBuilds` hint text in `plugin.ts`.** Rejected: the fork verified on this host that pnpm 10 enforces the git-hosted build allowlist from `pnpm.onlyBuiltDependencies` in the profile's `package.json`, so upstream's line sends the operator to the file pnpm ignores.
- **Keep the fork's local `message()` helper in `section-store.ts`.** Rejected: `dsh-value` exports `errorMessage` for that conversion, so the helper is a second spelling of one behavior.
- **Choose upstream's side of `main.ts`.** Rejected: the fork's file carries its own startup sequence, its `onFailure` handling, and a menu policy that builds the devtools items only on Windows, so upstream's refactor has to land inside it.
- **Refresh the release-numbered fixtures to the new version.** Rejected: `desktop-build-version.spec.ts` rejects a build version that leaves the product release numbers, and `plugin-compatibility.spec.ts` needs an exemption value that differs from the runtime version and is not a range; a refresh would remove the distinction each case exists to draw.

## Testing

`pnpm run constraints` requires each of the 43 manifests upstream does not ship to equal the root version and passes on the merged tree. `pnpm run typecheck` covers both compiler faces (exit 0), and `pnpm run lint` exits 0 with no diagnostics. `pnpm run doc-sync` reports 43 gates passed and 1 failed, the failure being `verify-package-paths` on `docs/TECH_DEBT.md:225`, whose quoted path was deleted from the tree long before this merge; the generator checks over the conflicted catalogs pass (`verify-tool-catalog`, `verify-config-catalog`, `verify-doc-graphs`, `verify-dependency-catalog`, `verify-persistence-catalog`, `verify-client-catalog`, and `gen-module-graph --check` reporting 3 artifacts up to date). `pnpm exec tsx scripts/release/verify.ts --family dsh` resolves 352 members at `0.1.7-rc.1` with the publish order resolved. `pnpm exec vitest run --config vitest.snapshot.config.ts snapshots/acp` replays 16 cases keyless, `packages/client/better-sidebar` runs 170 files and 2071 cases with 5 skipped, `packages/client/ui-patent-teams` with `apps/desktop/tests/desktop-build-version.spec.ts` and `packages/boot/app-boot/tests/plugin-compatibility.spec.ts` run 5 files and 131 cases, and `apps/cli/tests/plugin.spec.ts` with `apps/cli/tests/plugin-failure-hints.spec.ts` run 18 cases. `pnpm run hygiene` passes all 19 of its gates (exit 0), the `vendor rescope` check among them. `pnpm run verify-translation-pairing` accepts every edited pair.
