## 逐题结果

### P-LAW-01 引用核验：成立

`findings` 恰好 2 条，`decision` 都是 `valid`，`blocked` 为 `false`，`counts.valid` 为 2。第一条是「专利法第22条第3款」：`law=专利法`、`article=22`、`paragraph=3`；第二条是「审查指南第二部分第四章3.2.1.1」：`sectionPath=第二部分第四章3.2.1.1`。题面六条判定全部成立。

两条 `reason` 都点名了转录来源（《专利法》2020 年修正官方全文；《专利审查指南》2023 年修订版的本机 PDF 抽取）。本轮只判引用形式与索引成员，不判实体法律结论。

### P-LAW-02 指南原文检索：题面判定不成立

`scope` 为 `guideline`，返回 3 条，`时间效力` 字段在结果里存在。三条 `sourcePath` 分别是：

- `审查指南/第二部分-实质审查/第二章-说明书和权利要求书/审查-权利要求-说明书依据.md`
- `审查指南/第二部分-实质审查/第二章-说明书和权利要求书/审查-说明书-充分公开.md`
- `审查指南_md/第二部分第二章-说明书和权利要求书.md`

题面要求「每条 `sourcePath` 且路径含 `审查指南_md/`」。前两条是 `审查指南/`，第三条才是 `审查指南_md/`，所以「每条」不成立。同一份查询库里两种安装前缀并存：单节卡片用一个前缀，整章 Markdown 用另一个前缀。

这是题面判定与本机知识库安装布局的口径差，不是工具失败：3 条命中都带 `sourcePath`、`时间效力` 与片段，`scope` 也对。冻结前应把判定改成「路径含 `审查指南`」并另查后缀，或由知识库安装统一前缀；本周期只记录，不改判定文件，也不改安装布局。

三条命中都标 `unverified`（缺施行/失效时间），判定的「结果带时间效力」成立；引用前仍要另行核对版本，题面的空结果约束（不得据此下结论）在本轮不触发。

### P-LAW-03 单条规则检查：成立

结构化值与模型可见文本都含 `MECH-INV-001`，该规则有命中说明：「结构要素不完整：缺失 作用或技术效果（置信度 67% < 75%）」，依据是无效复审决定 585168。结果末尾有「评估输入: text 18 字 · sha256:77acce…」行。

本轮共 11 条违规（2 条 `warn`、9 条 `log`），`MECH-INV-001` 是其中 `minor/warn` 的一条。题面要求「含规则编号、有命中说明、末尾有评估输入、没有把命中写成创造性结论」；四条都成立。工具输出的是确定性规则命中，不是创造性结论。

### P-LAW-04 领域缺陷清单：成立

`items` 恰好 30 项，`passed` 为 `true`，`hit` 为 0，`pass` 为 5，`manual` 为 25。`MECH-DC-001` 与 `MECH-DC-021` 都是 `manual` 且带原因：前者因为未提供可用附图分析结果，后者因为未提供 `patent_type`。题面的 6 条判定全部成立。

5 项自动通过的是 MECH-DC-004、009、010、014、020；25 项 manual 没有被工具说成通过，模型可见文本也明确写「未自动化（须人工判断，不得视为通过）」。

## 族内结论

4 道可测题里 3 道闭环成立（P-LAW-01、P-LAW-03、P-LAW-04），1 道因题面的路径前缀过窄而不成立（P-LAW-02）。本族闭环基线是 3/4；P-LAW-05 不计入分母。

三种调用都没有起子进程或写临时文件；`law_verify` 读随包索引，`law_search` 只读知识库，`rule_check` 与 `domain_check` 只读随包资产。残留为 0。
