# 第一轮 32 条遗留的处置台账（B1）

本文件承接 [11-patent/03-decisions.md](../11-patent/03-decisions.md)。B0 对账后，未修项为 32 条（21 条标「待决策」，11 条标「未修」并给出具体原因）。本文件只记录第二轮如何处置，条目证据仍以 [11-patent/01-findings.md](../11-patent/01-findings.md) 为准。

## 处置口径

- 本轮实施：修复方向唯一、不改变对外能力，或只让既有能力如实报告。按批次落地并跑门禁。
- 需确认：改动会落在领域判据、模型可见契约或产品呈现上，先取得口径再动手。
- 需外部证据：缺真机、真实语料、官方数据或外部 API 契约，本轮先补证据或单列专项。

## 需确认的四组

### 第一组：领域启发式（F-PAT-072、085、086、103）

四项都是「判据宽严」而非实现错误。建议只修 072 与 086：072 把「约」「左右」限定在数值上下文，086 要求出现标准号形式才算引证；085 的组件标号与 103 的电路结点需要先有真实语料或制图规范，维持现状并记录理由。

### 第二组：模型可见契约（F-PAT-101、121、135）

建议修 101 与 121：101 把「参考标号：N」改成请求数加已落图数；121 把「命中 N / M」改成命中加总数，并补 `category` 在三种模式下的语义说明。135 的「未核验」原因分类要动法条索引的 finding 结构并补 31 个容器条目，建议随法条索引专项处理。

### 第三组：UI 口径（F-PAT-152、153、154、155、156）

建议修 152、153、154：152 在分段条中拆出失败与已取消；153 用完成事件的 `seq` 取最近完成；154 把「已派发」限定为有 assignee 的任务、成员限定为未离队。155 建议只做 README 披露（52×6 条翻译单列）。156 建议维持仓库惯例（81 个客户端包中 57 个英文标题是 slug），只在本文件记录差异。

### 第四组：契约与外部数据（F-PAT-118、119、120、131、132②、133、134）

建议只修代码层且不改资产的项：131①（PCT 费用行归入进入手续）、134②（未核验时扣留合计）、134③（`figures` 返回契约写明源件与入文位图）、120（规则资产加载期校验，现有资产已合规）、133 的 PDF 字节上限与 DOI 归一、132②（列表槽位）。需要资产或外部契约的项（131③ 日历、134① 变更费两档、118/119 的事件契约扩展、133 的 arXiv 输入分类）延后到各自专项。
