# 审查意见答复

对审查意见通知书作出答复，产出意见陈述书与（必要时）修改后的权利要求书。论证按「事实 → 规则 → 论证」三层组织，**不按审查意见项号逐条铺陈**。

## 必查清单（先查再分析）

- 先定答复期限，再据期限建提醒（两步）：①用 patent_deadlines 取本次答复期限——给出 patentType、filingDate、claimsPriority，并把收到的通知书放进 notices（如 {kind: 'office-action-first', dispatchDate: '…'}）；期限的月数与起算口径由该工具按现行细则与指南给出，不要自行写死月数或口算，也不要因为材料里没写送达日就按申请日估算。②用 schedule_create 按返回的 dueDate 建两条提醒——到期前 15 天与到期日当天各一条：at 传对应时刻（RFC 3339 带偏移，或 {date, time, time_zone}），title 写案件与事项、日期只进 at、提醒内容进 prompt；提前天数默认 15 天，可按当事人要求调整。提醒只送达创建它的会话：单人模式即当前会话；团队模式由队长在主会话创建（子代理调用会被拒，不要转派）。
- 用 patent_workflow_run（manifestId=patent_oa_response_v1；input=通知书正文，claims=权利要求书）跑解析与撰写：parse 阶段为确定性解析，claim-chart 阶段（mode=oa-response）以解析出的引用文献为目标逐要素映射到权利要求（目标自动派生，无需手传 chartTargets），response-plan 阶段把逐理由策略、必答段落与逐权项修改对照拼成计划骨架，generate_keywords 阶段按通知书正文生成检索关键词（上位/下位/同义词），draft 阶段读到解析结果、对照表、答复计划与这批关键词，并把它们写成「证据与引用」一节的可执行检索方案（关键词、IPC/CPC 分类号、数据库与各自要核验什么）。本预设的前台运行在审批门直接询问用户：放行即继续，拒绝则带结果名暂停（此时传入 approveStageIds 会被拒绝）；后台运行仍暂停，并以 approveStageIds 续跑。
- 只做解析时用 parse_office_action（text=通知书正文）：返回驳回类型（按首现位置排序去重）、引用文献与相关性类别、涉及权项、审查员论点。未标注相关性类别的文献不推断类别；涉及权项是同句共现、不是审查员的权威对应，须人工核对；解析不判定理由是否成立。同一文献在不同位置的标注不一致时，结果含解析冲突（冲突源/候选值/采用依据），不静默取单一结论，须人工核对后再采用。
- 用 patent_wiki_search / patent_case_search 取对应驳回类型的审查标准与在先答复案例；法条、指南、判例的原文按纪律核验后引用，不凭记忆写条号。
- 正式出件用官方标准表格：正文写 100014 附页，表格用 100012 意见陈述书（模板库 `~/.dsh/patent-ops/templates/cnipa-标准表格/`）；口径见模板 `oa-response` 的 `references/conventions.md` §8。

## 答复流程

1. 定主策略：按解析出的驳回类型（充分公开 / 不清楚或不支持 / 新颖性 / 创造性 / 修改超范围 / 形式缺陷）确定主策略；多种类型并存时以最核心的驳回理由为主。解析器未命中具体条款时（`未识别条款`）不替文书定条款，按正文人工归类后再答复；正文出现解析器不单列类型的理由（如实用性 22.4、不授权客体 25 条）时同样按正文归类。
2. 答复方向四选一并写明理由：①纯争辩（不修改）——事实认定有误、结合无技术启示、区别特征认定错误；②修改+争辩——将从属特征并入独权即可克服；③混合策略——重写权利要求（增补区别特征/重新划界）并争辩剩余争议；④放弃答复——缺陷无法克服（如公开不充分涉及全部实施例）时须向当事人明示。（层级说明：response-plan 骨架的策略表是逐项理由的机器默认——争辩／修改／未识别条款时的争辩+修改；四选一是本案层面的方向判断，两者不一致时以本案判断为准，并在意见陈述中说明理由。）
3. **抽事实**：从申请文件与对比文件中抽出与争点相关的事实，逐项编号（F1…／P1…），每项一到两句并注明出处（权项号、说明书页码行号、对比文件段落号与附图标记）。事实只陈述、不评价——「与对比文件有本质区别」是论证结论，不是事实；结构性定位（如"说明书'发明内容'部分"）只用于工作稿，定稿须落到页码行号。
4. **立规则**：写明本案据以论证的法条条款号与《专利审查指南》节号（R1…）。条号须核验后引用，旧条号换算为现行条号；随包索引的指南节已转录 2023 年修订版正文，逐字引用前用 `law_verify` 核验命题是否落在所引节及其子节内；引 2026 年版（2026-01-01 施行）改动过的节时另行提供该版文本来源。
5. **做论证**：每条论证回指事实编号（F/P）与规则编号（R），按争点分节——新颖性、创造性、其他争点；审查意见项号只在需要审查员定位时以括注出现，不作小节标题。创造性走三步法：锁定最接近现有技术 → 逐条列出区别特征并按客观作用确定实际解决的技术问题（不得包含区别特征自身的指引）→ 反驳结合启示与公知常识认定，强调预料不到的技术效果。
6. 逐权项处理修改：修改后列出权利要求全文，且不得超出原说明书与权利要求书记载的范围（A33）；修改须针对通知书指出的缺陷（现行细则第 57 条第 3 款）。修改对照表与修改后全文是两份、都要写，不合并：表 1 登记过的独立权利要求，全文必须能查到（口径见模板 `oa-response` 的 `references/conventions.md` §11）。
7. 形式缺陷（笔误、附图标记、摘要、用词）集中列一节，逐项写处理方式与依据，不与实体论证争篇幅。
8. 论证按法定判准组织，不以计数或复述替代：充分公开的答复围绕「本领域技术人员能否实现」陈述（说明书给出的技术手段如何制造、如何使用、如何解决技术问题），字词出现次数、篇幅与文献数量都不是 26.3 的判准；同一段说明书原文不复述第二遍，需要再次引用时指明出处而不整段重抄。

## 约束

禁止编造实验数据；禁止无逻辑链的空泛断言；凡引用法条/指南/判例须带来源（含 source_path），拿不出来源就删除该断言。

产物与推理分开：意见陈述与修改后的权利要求直接给结论与论证，不要把"先推理一遍"的中间过程抄进产物；需要留痕的中间判断写进工作稿。撰写与答复类任务不要求逐步显式推理——推理阶段形成的框架一旦写进定稿，会连同其中的错误被后续段落沿用。

删减纪律：答复正文的预算是全篇 4000 字可见字符（去空白、不含表格与权利要求全文），逐节预算见模板 `oa-response` 的 `references/conventions.md` §10，渲染前由槽位硬上限 fail-closed。四条——通知书未提出的争点不设节（不留空节、不留「本案不涉及…」占位句）、不写「本部分应当说明…」式模板指导语、每句都要有读者理由、超预算先整段删再打磨句子（同义改写到 4000 字仍算超预算写作）。`patent_workflow_run` 的 draft 阶段按预算写，其后的 `tighten` 阶段删到预算内、`slop-gate` 阶段按预算判篇幅；定稿前按模板 `references/checklist.md` P0 的篇幅三条自查。

## 输出

意见陈述书 + 修改对照表（逐权项列修改前/修改后/修改依据）；正式交付按 patent-document-polish 走模板渲染（`oa-response`）。

## 质量门禁与人工确认

答复策略、修改范围与是否放弃答复先 ask_user_question 确认再起草；结论附免责声明；交付前经 patent-quality-gate。

起草完成后、交付前用 rule_check（scope: 'patent-oa-response'，notice 传通知书正文）自检：该 scope 只评估本作业的规则域，规则的适用前提让未讨论主题的完整性检查保持沉默，故命中即针对本文书。逐条处置命中——改正文或在不采纳说明里写明理由；PR-OA-005（计数式论证）与 PR-OA-006（重复引证）命中即为第 8 条失守，须改写论证而不是调整措辞。提供 notice 时另评估双输入规则——PR-OA-008（驳回理由覆盖）与 PR-OA-009（未提条款引用）；未提供 notice 时工具会显式列出未评估的双输入规则。
