## 审阅方法

- 导出可达性：反向解析 54 个文件的每个模块级导出（含 `export { … } from`），统计生产代码与测试的消费者。结果：无零引用导出，无文件内私有死符号。
- 仅测试/同文件消费的 10 个导出逐个归类：`ConsumeRef`、`RevisionLogResult`、`WorkflowStageBudget`、`ClearStageOutputsOptions`、`ResponsePlan*`、`CreateLlmModelPortOptions`、`PatentWriteRoot`、`Json*Result` 是公开函数的返回/参数类型；`MATTER_LAYOUT_DIRS`、`MATTER_LOG_FILENAME`、`MIN_PDF_BYTES`、`datedOutputDir`、`stripCodeFence`、`revisionLedgerVerdict`、`DRAFT_QUALITY_SIGNALS`、`WORKFLOW_STRATEGIES` 只被同文件或测试消费，且均未从包根导出。
- 静态清单：`new Error(`、无错误绑定的 `catch`、`as unknown`、`as string`、`v8 ignore`、`TODO` 逐条回源。
- 高风险路径精读：`engine.ts` 超步/取消/中断/合并、`node-policy.ts` 重试与超时、`adapter.ts` 阶段输出与回退路由、`checkpoint.ts` 持久化与批准、`subprocess-deadline.ts` 计时器、`graph/domains/citation-check.ts` 接地判定、adversary 五步、notice 解析、quality 折叠、`paths.ts`/`safe-path.ts` 越界防护。
- 取消透传：12 处 `llmNode` 与 `numeric_range` 的 `callLlm` 逐处核对；`callLlm` 的取消转换与图引擎超步边界行为对读。
- 覆盖率基线纳入六个包的测试：patent-core、patent-tools、patent-rule、patent-workflow，加上 patent-data 与 tool-literature（`parseStoredJsonRecord` 的非对象分支、`resolveDatedOutputDir` 的显式目录分支分别只在两者）。
- 未委派子代理。

### 已排除的候选

| 候选 | 排除理由 |
|---|---|
| Reducer 只生产使用 `last_write_wins`（`GraphBuilder.setSchema` 仅测试调用） | `append`/`union`/`merge_map`/`fail_on_conflict` 是图 Schema 的既定扩展点，`setSchema` 从 `graph/index.ts` 可达；按本轮「不删未接线能力」保留。`append` 把数组值整体当一个元素、`union` 展开数组，是「追加一个值」与「集合并」的语义差，不是遗漏的提取。 |
| `DegradedOptions.code` / `_error_code` 无生产者与消费者（`llm.ts:29-34`、`handler.ts:37`） | 属 B4 已签收的 atoms 面；当前无 handler 传入、无工具读取，能力保留，未在本批改动。 |
| 图路径 `citationCheckNode` 不传 `receiptCitationIds`（`citation-check.ts:146`） | 台账收据由 `priorArtReceiptCitationIds(docs)` 从检索命中推导，图节点已用 `extractDocIds` 生成同样的 D 标号；atom 路径（`citation.ts:72`）覆盖收据精确匹配。两条入口的差异是「缺引用文本时降级 vs 跳过硬校验」，两处均有文档说明。 |
| `computeOverallConfidence` 与 `computeReviewConfidence` 的加权平均（`divergence.ts:72-80`、`review.ts:361-376`） | 空争议时的返回值与论证强度调整不同，提取只会留下两行；合并会把「无争议的默认置信度」这一判定耦合到一起。 |
| `requireRuleEvaluator`/`ruleGateNode` 抛裸 `Error` 而其余图错误用 `GraphEngineError` | 构图期配置错误，无调用方按错误类判定（全仓没有 `instanceof GraphEngineError` 的生产代码）；改类型属于无收益的公共行为变更。 |
| `cloneState` 的 JSON 兜底（`state.ts:18-20`） | 仅当状态含函数/类实例时进入；`JSON.stringify` 对循环引用抛错是既有失败面，不在本批扩围。 |
| `manifest.ts` 的 `new RegExp(..., 'i')` 校验 vs 运行时 `'gi'` | 语法校验与标志无关，非法模式在装载期即被拒；仅标志不同，不构成两处判定。 |
