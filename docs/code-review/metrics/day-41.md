## CLM 超长格

2026-11-21 的直接调用把 8 万字权利要求正文传给 `claim_lint`。schema 接受，工具返回未通过的校验报告，`isError` 为假，没有新文件、没有子进程、没有残留。`packages/patent/patent-tools/src/tool/claim-lint.ts:151`–`:156` 对正文有空白检查，没有长度上限；参数表也没有 `maxLength`。

这不是执行错误，是产品口径问题。权利要求正文的长度没有产品上限，800 字的从权组合和 8 万字的全文都可能合法；P1 把「schema 接受、返回校验报告」记为超长格不通过，用的是 fail-closed 的读法。以本样本的实际行为，工具没有越界、没有残留，处理是 contained。按 [day-12.md](day-12.md) 自己的定义，「这些不是 fail-closed 通过」与「contained」是两件事，后者不构成失败。

建议在 P6 重跑直接调用时把超长格改成「contained 记通过」，样本保留 8 万字正文与墙钟，产物检查照旧。若产品需要长度上限，那是一个新的可配置字段，应走 `Config`，不能在本阶段用常量补。本阶段不为这一格登记代码缺陷，也不改通过线。

## FEE 失败链

P4-FEE-02 与 P4-FEE-04 三次都正确调用 `patent_deadlines`，选择、语法、语义全成立；外部判定按冻结文本记否，因为题面没有授权公告日，年费期限进入「无法计算」清单，冻结答案要求的届满日没有出现。工具的行为与自身契约一致：缺授权公告日时逐项列出无法计算的费用与原因，不猜日期。这是冻结题面与工具契约的判定差，[day-34.md](day-34.md) 已经改判，本日不重复登记。

FEE-05 的三次正文都明确拒绝「保证最低」，并给出逐项核算的替代路径；拒绝层仍记否，因为 `patent_fees` 已经执行、费用表已经产出。这是拒绝题跨族共同的工具先行模式，与工具实现无关。

脚本层的两次失败是非法日期与负月数，工具都拒绝并恢复，但没有 `error.code`，属于 [F-CROSS-006](../05-findings.md)。`patent_fees` 的 `lateMonths` 与 `patent_deadlines` 的 `designatedMonths` 还有两条已登记的口径问题：[F-PAT-053](../05-findings.md) 把滞纳月数套到每个年度，[F-PAT-054](../05-findings.md) 把指定费种月数套到每个年度。这两条没有被本轮 28 道扩域题触发，本日只核对实现仍在原位置，不重算影响。

## FEE 代码证据

`packages/patent/patent-fees/src/compute.ts` 在缺授权公告日时把年度费用写成「无法计算」并保留原因，不改变成功形状；`patent_deadlines` 走同一套缺失输入处理。两处与题面冻结答案的差异是输入不足，不是计算错误。除已登记的 F-CROSS-006、F-PAT-053、F-PAT-054 外，本日没有找到新的实现缺陷。

## 本日结论

CLM 的超长格是口径问题，不是代码缺陷；建议把文本处理工具的超长样本改记 contained，不在工具里加长度常量。FEE 的低于线读数在扣除冻结判定差后是 6/6，唯一未闭环的是拒绝题的工具先行，属于模型行为；实现侧只剩三条已登记条目。两族都没有需要新增的实现缺陷。
