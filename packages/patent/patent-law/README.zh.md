<a id="law-verify-tool"></a>
## law_verify 工具

law_verify 读取一段文本中的法条引用（或直接传入的引用），逐条对照本次部署随包的索引作出判定：《专利法》《专利法实施细则》按条，《专利审查指南》按归一化节路径。每条判定都带判定结果、本次部署对该判定的处置，以及理由。

这个工具存在的原因：法条核验此前散在四处互不相通的地方——工作流质量门禁里的静态主题表、规则资产里的条数上限、145 个规则文件里的 `legalBasis` 文本、以及一个并不随包交付的用户级基线文件——因此错误的条号可能一路通过。统一索引、统一解析、统一判定只固定"引用形式是否可核验"，不判断法条内容是否正确，工具也如实说明这一点。

<a id="citation-decisions-and-policy"></a>
## 引用判定与处置策略

| 判定 | 含义 |
| --- | --- |
| 已核验（`valid`） | 已索引、已按记录来源转录，且（给出命题时）该条承载所引命题：主题词点到该命题，或转录文本承载该命题。 |
| 与所引命题不符（`mismatch`） | 已索引且已转录，但所引款不存在，或所引条目未承载该命题而同一法律的另一条目承载了它。 |
| 未与条文对应（未判定）（`unmatched`） | 已索引且已转录，而该法律中没有任何条目在字面上承载该命题。 |
| 条号超出有效范围（`out-of-range`） | 超出条数上限，**且该上限本身已核验**。 |
| 索引中不存在（`not-indexed`） | 索引中没有该条，或本次部署没有该法的索引。 |
| 条文未转录（未核验）（`unverified`） | 已索引，但条文文本或核验来源仍缺；超出「未核验上限」的条号、其下各节也都没转录的指南条目同样按此报告。 |

命题比对靠两路信号，两路都是词法比对。第一路是条目声明的主题词：命题点到某个已收录的主题即视为承载。第二路是转录后的条文文本：命题的字符对中被该文本承载的比例（按该字符对在全部条目中出现的次数反向加权，法律反复使用的措辞权重低）须达到 `propositionSupport`。因此逐字引用一条条文即使主题词没点到它也能通过——这正是只看主题词会判错的情形：《专利法》第 47 条登记的主题词写作「视为自始不存在」，而该条文本写作「视为自始即不存在」。两路都不成立说明没有条目承载该命题，此时才报「未判定」；`mismatch` 留给有正面证据的情形：同一法律的另一条目确实承载了该命题。

指南按节路径索引，而一节包含它的子节，所以判定按整节进行：命题由所引节的子节承载时引用成立，理由里点出承载它的子节名；反过来，所引节下面的子节不会成为「命题的另一个归宿」而被判不符。只登记到部分或章一级的条目没有自己的正文，其判定完全由该部分/章下面各节作出——引用一章等于引用它下面全部节，逐字引用其中任一节都会通过；该章下面没有任何已转录的节时仍报「未核验」。

五种处置各对应一个 Config 字段（`onMismatch`、`onUnmatched`、`onOutOfRange`、`onNotIndexed`、`onUnverified`），取值 `block`、`warn`、`allow`。随包默认对「与命题相矛盾」和「已核验上限之外的条号」拦截，对索引缺口与「没有任何条目能判定」的命题只告警——这样部分转录的索引仍可用，而每一处缺口都可见。

<a id="law-index-assets"></a>
## 法条索引资产

`assets/law/` 每部文书一个文件（`cn-patent-law.yaml`、`cn-implementing-regulations.yaml`、`cn-examination-guidelines.yaml`）。每个条目记录条号或节路径、用于核对命题的主题词，以及转录来源：`text`、`sourceDoc`、`verifiedOn`。条数上限自带 `maxVerifiedOn`，因为一个没人核验过的上限不得产出「超出有效范围」的判定。

`assets/lineage/cn-patent-law-lineage.yaml` 记录《专利法》的五个修订版本（1984 年原始文本至 2020 年第四次修正），以及每条已索引法条的修订历史与当前状态。插件加载索引时一并读入该快照并交给 `rule-lock`，法条有效性与生效日期以沿革记录为准；快照未覆盖的法条回退到索引判定。沿革快照按修法事件手工维护，不按日历：新增 `revisions` 条目、更新受修订影响的每条法条、提升 `lineageVersion`，并重录来源与核验日期。文件缺失或格式错误会使插件加载失败，加载器测试钉住其结构。不排期持续抓取管道——专利法以年为单位修订，定时抓取只会增加监控、版本与复核成本，不会提高准确性；刷新由立法修订触发。

两部法律（法规）与指南节均已转录：每个条目带着它所索引条文或节正文的文本、该文本抄录的文书与版本、以及抄录日期。指南引用按所引节及其子节判定；只有其下已索引的各节都没有正文的条目才报「未核验」。后续修订版修改的指南节记在 `versions` 中，作为基础 `sections` 的覆盖；核验未指定 `revision` 时使用最新覆盖。

```yaml
- law: 专利法
  article: 22
  paragraphs: [1, 2, 3]
  topics: [新颖性, 创造性]
  text: <现行条文>
  sourceDoc: <官方文本标识>
  verifiedOn: 2026-01-01
```

随包索引覆盖《专利法》82 条中的 37 条、《专利法实施细则》共 149 条，索引 45 条。引用一条确实存在但未被索引的条文会报「索引中不存在」——这是索引的缺口，不是对该条号不存在的断言。文本是按官方修订文本逐字抄录、逐条记录来源的副本，未经人工回读复核，文件头对此有明确说明。

《专利审查指南》按节收录 85 条：其中 70 条是节级条款、带节正文，15 条是部分、章或节一级的容器条目、自身不带正文（正文在其下各节）。节正文由 `tools/guideline-transcript.py` 从官方 2023 年修订版全文 PDF 机械抽取，规则写在脚本的模块注释里：按坐标去掉页眉页脚与左边栏的法规号（法 26.3、细则 70.2 一类），按黑体标题定位节并把节的范围取到同部分同章的下一个标题为止（子节各归自己的路径，正文不重复登记），按段首缩进（x≥170）切段以抵消 PDF 的固定列折行，并丢掉源 PDF 里重复渲染的同一文本行。`--write` 按这些规则重写条目的 `text`/`sourceDoc`/`verifiedOn`，`--check` 逐字复核索引与源 PDF 的抽取结果是否一致；源 PDF 不在本仓库中，缺失时脚本报「未核验」而不是静默通过，因此索引中的转录与来源记录才是唯一的存证。抽取结果另与两份独立的本机 Markdown 转换逐节比对：126 项四元组包含度检查中 113 项达到 1.000，其余差异逐条查明为转换端的问题（化学式下标被拆、单独数字被吞、边栏法规号混入句子）。加载器把转录记录当作全有或全无：`text` 已记录但缺 `sourceDoc` 或 `verifiedOn`，或记录了来源却没有 `text`，都会使插件加载失败。

`versions` 目前只有一项 `2026 年修订版（2026-01-01 施行）`，收录已确认修改的 3 节（第二部分第一章4.4、第四部分第三章2.1、第四部分第三章3.3）。这 3 节的正文按 2025-11-13 局令第84号修改对照表的新栏转录，并按其中的颜色标记剔除删除文字；其余 61 条节级条目仍是 2023 年文本，不声称已按 2026 年版更新。`verifyCitation` 未指定 `revision` 时，如果现行修订版（`supersededBy`）已有转录，则按顺序应用截至最新已转录版本的每个覆盖；如果 `supersededBy` 指向尚未转录的版本，则使用基础文本与过时标记。指定 2023 年修订版时使用基础文本与 `staleSections`，指定索引没有的版本时报「未核验」而不是回退。

<a id="library-api"></a>
## 库 API

- `parseLawReference(text)` / `extractLawReferences(text)` / `formatLawReference(reference)` —— 引用形式：`专利法第22条第3款`、`《专利法》第二十二条第三款`、`A22.3`、`细则第112条`、`审查指南第二部分第四章3.2.1.1`。中文与数字之间的空格、全角数字、外层引号与并列续引（`专利法第22条、第23条`、`第22条第2款、第3款`）都会归一；续引的 `raw` 只记该 token（`第23条`），因为承继的法律名并未写在那里。
- `scanUnrecognizedCitations(text, references)` —— 解析器未能识别的、形如法条引用的片段；部分抽取因此可见，不会读成一次完整核验。
- `parseCnNumber(text)` / `formatCnNumber(value)` —— 中文数字与阿拉伯数字互换（`一百一十二` ↔ `112`）。解析器接受 `〇` 与 `千`；畸形数字返回 null，而不是读成另一个数。
- `loadLawBaselines(dir?)` / `parseLawBaseline(source, origin)` / `findArticle` / `findSection` —— 索引加载与校验，缺失即 fail-loud。
- `verifyCitation(reference, baselines, options)` / `verifyCitations(text, baselines, options)` —— 判定。
- `queryValidity(query, baselines, lineage?)` / `decideValidity(reference, baselines, query, lineage?)` —— 四态有效性判定；给出沿革记录时以其为准，覆盖索引按转录状态得出的结论。
- `loadLawLineageFile(path)` / `parseLawLineage(source, origin)` / `queryArticleLineage` / `queryArticleAtDate` / `queryDiffBetween` / `queryStatusSnapshot` —— 随包沿革快照及其时点查询。
- `ruleLockAtom` / `RuleLockHandler` / `lockProvisions` —— `rule-lock` 规则锁定门。接入沿革数据后，`effectiveDate` 取最近一次修订的生效日期；未接入时回退到条目的 `verifiedOn` 转录日期。
- `createOverlapIndex(entries)` / `textOverlap(index, proposition, text)` / `topicOverlap(topics, proposition)` / `PROPOSITION_SUPPORT_DEFAULT` —— 命题比对的两路信号。
- `resolveCitationPolicy(finding, policies)` / `renderCitationFindings` / `renderCitationRows` —— 处置与渲染。

本包不发布服务：索引是只读资产，工具是进程内消费者。第二个消费者直接 import 本库（如同 `dsh-patent-core` 作为纯库被消费），而不是为一个运行期不变的值解析服务。

<a id="configuration"></a>
## 配置

Schemastery 配置；`baselineDir` 可选，其余处置字段均有默认值。

| 键 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| baselineDir | string | 随包资产 | 存放法条索引 YAML 的目录。缺失、为空、格式错误，或缺少三部文档之一，都会导致插件加载失败。 |
| lineageDir | string | 随包资产 | 存放 `cn-patent-law-lineage.yaml` 的目录。沿革快照在插件加载时读入；文件缺失或格式错误会使插件加载失败，不会静默退化为仅按索引判定。 |
| cnlawEnabled | boolean | `true` | 本部署是否运行本机 cnlaw 法律底座。`false` 声明没有底座，声明段改为给出回退通道而不是端点。 |
| cnlawSearchUrl | string | `http://127.0.0.1:8100` | cnlaw 语义检索端点，声明给模型。 |
| cnlawGraphUrl | string | `http://127.0.0.1:8001` | cnlaw 图谱/案件端点，声明给模型。 |
| onMismatch | `block` \| `warn` \| `allow` | `block` | 对「所引条目不承载该命题、而同一法律的另一条目承载了它」或「所引款不存在」的处置。 |
| onUnmatched | `block` \| `warn` \| `allow` | `warn` | 对「该法律中没有任何条目承载该命题」的处置。 |
| onOutOfRange | `block` \| `warn` \| `allow` | `block` | 对超出已核验条数上限的引用的处置。 |
| onNotIndexed | `block` \| `warn` \| `allow` | `warn` | 对索引中不存在的引用的处置。 |
| onUnverified | `block` \| `warn` \| `allow` | `warn` | 对已索引但待转录条目的处置。 |
| propositionSupport | number | `0.75` | 条目的转录文本须承载命题字符对的加权占比下限，达到才视为该文本支撑该命题。 |

<a id="model-experience"></a>
## 模型体验

### law_verify 工具

#### 模型看到什么

一个名为 `law_verify` 的注册工具，可选 `text`（从中抽取引用）、可选 `references`（逐条给出的引用）、可选 `proposition`（这些引用支撑什么）；`text` 与 `references` 至少给出其一，且空串或纯空白且未给 `references` 的 `text` 按输入错误处理，而不是一次没有发现（findings）的成功检查。返回的是规范化判定列表——原引用、法律、条号、款号、项号、节路径、判定、处置、理由——外加 `blocked` 标志、各判定的计数，以及未参与判定的 `unrecognized` 片段，渲染为 Markdown 表格，后附缺口或拦截所意味着的说明。以并列续引开头的引用承继前一条的法律与条号；解析器无法识别的片段列入 `unrecognized`，不会被静默跳过。工具描述写明六种判定、未转录条文永不报成已核验，以及无法解析为单条引用的输入按输入错误处理。

#### Token 影响

工具启用期间每次请求固定付出定义开销；每次结果是一张短表加说明，仅在压缩前重发。

#### KV Cache 影响

仅追加；新可见的结果文本跟随可复用的请求前缀，不会使既有 KV 缓存条目失效。

### cnlaw 声明段

#### 模型看到什么

一段静态系统提示，名 `patent-law:cnlaw`，与其余专利域段落同序，内容是声明的端点——`cnlawSearchUrl` 对应 `/search`、`/search/decisions`、`/search/judgments`，`cnlawGraphUrl` 对应图谱、案件与 IPC 路由——并写明部署挂载 MCP 桥时由 `mcp__cnlaw__*` 工具取而代之；`cnlawEnabled=false` 时改为写明本部署没有底座、应走哪些核验通道。人设与专利技能都以「cnlaw 声明段」称呼它，因此随包文本不出现端口。该段同时声明指南通道：索引只含法条与判例，端点查不到指南并不说明被引的节号不存在——规则原文取自部署的外接 IP 知识库（`law_search` 的 scope=guideline 取指南全文、scope=law 取法规条文；`patent_kg_query` 的 node_type=GuidelineRule 与 `patent_wiki_search` 取规则卡片；`patent_case_search` 取适用规则的决定），取不到的节号保持未核验，不得凭记忆补全。仅在挂载了提示注册表的组合里注册该段；没有它时工具照常工作。

#### Token 影响

插件挂载且存在提示注册表时，每次请求固定付出该段开销；文本不含逐轮数据。

#### KV Cache 影响

静态：文本在插件加载时由 Config 算出，按定义即稳定，进入稳定前缀缓存且不会使既有条目失效。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与暂缓事项

- **转录文本是机械抄录，不是复核。** 每个法律条目的 `text` 是官方修订文本的逐字副本，因此「已核验」的含义是该条存在、已转录、且承载所引命题——不含"由具备资质者回读过副本"的意思。部署在依赖这些条目之前应自行回读复核。
- **法律覆盖面是部分的。** 《专利法》索引 82 条中的 37 条、《专利法实施细则》共 149 条，索引 45 条，因此一条存在但未被索引的条文会报 `not-indexed`，尽管条号有效。两部法律的条数上限均已核验，超出 82 或 149 的条号判「超出有效范围」。
- **《专利法》的主题词已改用 2020 年修正编号。** 现有技术抗辩、不视为侵权、合法来源三组主题词原本按 2008 年修正的 62/69/70 条收录，现改到 2020 年文本承载它们的 67/75/77 条；62 条改按其 2020 年文本的主题（强制许可使用费）。
- **《专利法实施细则》的主题词已对照转录条文核对。** 转录条文时发现当时已索引的条目中有 9 条挂着别的条文的主题词（第 42 条挂着分案申请，而分案申请在第 48 条；第 114 条挂着印花税，而现行细则第一百一十条列举的费种与官方缴费指南都不收该费），已按各自承载的条文重写。
- **指南节已转录，但只有 3 节带 2026 年文本，路径与主题词尚未按该版重核。** 64 条基础节级条目带 2023 年修订版的节正文（`versions` 中的 3 条覆盖其同名节），因此指南引用现在会判成 `valid`、`mismatch` 或 `unmatched`；部分与章一级条目不带正文，其判定由该部分/章下面各节作出，其下无已转录节时才报「未核验」。有四个这样的章级条目其下没有任何已转录节——第一部分第四章、第二部分第六章、第二部分第七章、第二部分第十章——因此引用它们时在该章转录之前始终报「未核验」。路径取自本仓库自身的引用，其中三处曾指向的不是该节、甚至不是一节——「技术领域」挂在 2.2.1，而 2023 年修订把该节编为 2.2.2；第九章写作「2.0」，而该修订写作「2」；第一部分第一章 2.3 根本不是一节——已逐行改到它所指的节，并另按该节自身内容重写了五行主题词。转录节正文时又订正一处：送达规则原登记为「第五部分第二章2.3.1」，而第五部分第二章是专利费用，送达规则在第五部分第六章2.3.1（`patent-deadline` 的电子送达依据串随之订正）。`guideline-citation-coverage.spec.ts` 只管路径是否落在索引里；主题词是否属于该节，只有节正文能核对。2026 年版《专利审查指南》（2026-01-01 施行）已修改本指南：本地修改对照表列出的 57 处改动中，已确认 3 处落在本索引的节上（第二部分第一章4.4、第四部分第三章2.1、第四部分第三章3.3），这 3 节已按对照表转录到 `versions`；其余节仍为 2023 年文本，不声称已更新。对照表还把第二部分第九章若干节列在新编号下，本机有修改对照表但没有 2026 年合订全文，故索引路径是否随该版改动编号尚未重核。
- **无效宣告章节已入索引，`paragraphs` 登记的是条文自身的款号。** 索引现有第 69 至 76 条（无效宣告：请求的提出、增加理由或补充证据、请求书的转送与指定答复期限），以及随包工具、规则资产与无效理由表引用的第 39 条、第 49 条、第 110 条、第 113 条。款号只按条文自身分段登记：某一款内以「（一）…」编号的各项是款内的项，故第 20 条是五款，其文本虽有十行。`statute-citation-coverage.spec.ts` 用同一套引用解析器扫描源码、规则、技能与 preset 的细则引用（不含索引自身转录文本中的引文），限定在索引已有的条号上；该条号是否承载所引命题，仍由 `topics` 命题核验回答。
- **命题匹配是词法匹配，而且它是筛子，不是复核。** 两路信号都比字符：主题词须出现在命题中或反之，或命题的字符对在转录文本中的加权占比达到 `propositionSupport`。用同义表述而两路都不点到的命题报「未判定」，须人工阅读；与法律共用套话（「国务院专利行政部门」）的命题仍可能通过一条并非所指的条文，因为反向加权只是压低该字符对的权重、并没有把它排除。主题词与转录文本须一并维护。
- **项号只报告、不核验。** 索引登记的是款而不是项；引用到 `第X项` 时按条与款判定，项号只在结果里回显。需要拒绝错误项号的部署要另建项级索引或另做检查。
- **未识别的片段是警告，不是拦截。** `unrecognized` 列出解析器无法识别的、形如法条引用的片段；它们没有参与判定，本身不会让 `blocked` 为真。把非空判定表当成完整核验的调用方还须检查这张列表。
- **紧凑形式 `A22.3` 只在词边界被接受**，且一律读作《专利法》：若某部署需要对其他法律使用该形式，需要自己的引用读取器。
- **畸形中文数字不会被猜成别的条号。** `第十十条`、`第十二三条` 不产生引用；解析器只接受法律实际使用的写法，其余返回 null，因此笔误不会被读成另一条。
- **指南索引以节路径为键。** 归一化无法复现的写法（例如比捕获的节尾更深的层级）会落进 `not-indexed`，不会被猜成另一节。
- **`patent-rule` 仍保留自己的条号上限。** 专利 preset 已挂载本插件，模型会先跑 law_verify；`patent-rule` 的条号上限仍自行作决定，它只把《专利法》条号限制在 82 以内，不逐条持有对应行。因此本部索引报为 `not-indexed` 的引用会被它放行——第 11、50 条即属此列。把该上限改读本部索引仍属后续工作：规则只按条号作决定，本部索引按条目作决定。
- **基线正确性属于内容，而非运行期观测。** 基线的正确性是内容属性，任何运行期观测都不能独立证伪；可机械检查的部分（引用解析、条与节存在性、条数上限）是门禁执行的检查。
- **声明段说的是部署声明了什么，不是有什么可达。** 两个端点都不在加载时探测，因此声明了但已停掉的服务在实际调用失败时才暴露；人设的回退纪律覆盖该情形。部署换了地址却没有更新 `cnlawSearchUrl` / `cnlawGraphUrl` 时，声明段仍声明旧端点。
- **指南通道是声明，不是校验。** 该段点名检索工具（知识库检索与规则卡片工具）；本包既不调用它们也不核验某个指南节号是否真的存在于其中，故一条引用只与模型实际执行的检索同等可靠。检索为空只对该次检索式成立。
