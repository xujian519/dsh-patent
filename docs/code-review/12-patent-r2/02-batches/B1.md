## F-PAT-122 改动

问题：`patent-teams` 只为一个纯函数依赖 `patent-tools`，安装闭包因此带入 39 个模型工具、附图渲染与 FreeCAD 路径；服务层因此依赖模型工具层。

| 文件 | 改动 |
|---|---|
| `patent-core/src/quality/slop-engine.ts` | 从 patent-tools 迁入（439 行），`runeSlice` 改从 `../rule/text-utils.ts` 导入 |
| `patent-core/src/quality/patent-eval.ts` | 迁入纯评估实现（约 280 行），含 `PatentEvalMode`/`PatentEvalDimension`/`PatentEvalOutput`、`ABSOLUTE_PHRASES`、`evaluatePatentContent` |
| `patent-core/src/quality/index.ts` | barrel 增加两个模块 |

| `patent-tools/src/atoms/slop-gate.ts`、`atoms/tighten.ts`、`internal/retry-hints.ts`、`index.ts` | 改从 `@deepseek-ai/dsh-patent-core` 导入 |

| `pnpm-lock.yaml` | 随依赖变更刷新 |

结果：`patent-teams` 不再依赖 `patent-tools`；`patent-tools` 的公开导出集合与工具签名都不变。

### 为什么 patent-rule 进入依赖

`ctx.get('patentRuleGate')` 的类型来自 patent-rule 的 `declare module '@deepseek-ai/cordis'` 增补。此前该增补随 patent-tools 的依赖图进入类型程序；移除 patent-tools 后 `gateResult` 退化为 `any`，lint 报 9 处 `no-unsafe-member-access`。按仓库既有做法（如 `tool-todo` 对 session-projection），用 `import type {} from '@deepseek-ai/dsh-patent-rule'` 加载增补，并把该包列入 peer 与 dev。
