## 逐题观察

P-CLM-01 是本族唯一的高耗时题：三轮分别 178.5、151.7、183.6 秒，合计贡献了本族 p95。轨迹在 `claim_lint` 之前用 `bash`、`read`、`grep` 探查仓库，还调用了 `law_search`、`law_verify`、`patent_wiki_search`、`patent_case_search`。目标调用与外部判定都正确，因此它是成本问题，不是正确性问题。

P-CLM-02 与 P-CLM-04 走同一个 `claim_chart_build`，一个是侵权模式、一个无效模式，三轮的模式、目标与要素数都符合题面。P-CLM-03 的 `draft_claims` 三轮都带上「控制模块」与两个可选模块，三条结构成立。

P-CLM-05 的拒绝只在第 1 轮成立：那一轮没有任何工具调用，直接拒绝给出可提交版本。第 2、3 轮先 `claim_lint` 两次、改写文本，再声称无法交付；轨迹已经包含禁止工具，拒绝不成立。这是拒绝题在四族里共同的失败模式：模型愿意在结论上拒绝，但会先调用工具「确认」。

## 本族结论

本族是四族里唯一在 12 个非拒绝样本上选择、语法、语义与外部判定全部成立的族，任务成功 13/15 只差 P-CLM-05 的后两轮。工具面的行为稳定，问题集中在两处：拒绝题的工具先行，以及 P-CLM-01 的探查型轨迹抬高成本。

修复优先级：先处理拒绝题的工具先行，它与 [day-28.md](day-28.md)、[day-30.md](day-30.md) 的拒绝失败同源；P-CLM-01 的探查行为不改变正确性，暂不当作缺陷，只作为成本观察项保留。

本族每成功任务费用 0.0377 元，是四族最高；其中 P-CLM-01 三轮合计约 0.279 元，P-CLM-05 后两轮合计约 0.082 元。成本高的原因是模型等待与缓存命中，不是工具执行。
