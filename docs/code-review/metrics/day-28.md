## 逐题观察

P-LAW-01 的前两轮都在 40 秒内拿到最终答复，第三条引用路径也判为已核验。第 3 轮首个 `law_verify` 已返回结果，但进程在 420.3 秒触顶，没有最终答复；按计划超时记失败，且不计入成功样本的耗时统计。这一题的三次调用本身都正确，风险在进程时限，不在工具选择。

P-LAW-02 是稳定偏离：三轮 `scope=guideline`、`limit=3`、`include_content=true` 都正确，`query` 却加上了「撰写」「充分公开」「要求」等词，题面要求「说明书」。结果 3 条，`sourcePath` 走 `审查指南/`，题面外部判定要求含 `审查指南_md/`。这是题面路径与测量路径不一致的冻结差，[day-22.md](day-22.md) 已登记。

P-LAW-03 三轮结果一致：`rule_check` 传 `scope=patent-mechanical`，命中 `MECH-INV-001`，末尾带「评估输入」与字数、指纹，没有把命中写成创造性结论。

P-LAW-04 只在第 1 轮多传 `patent_type`，30 项清单变成 7 项自动通过、23 项人工，`MECH-DC-021` 也不再是人工。后两轮只传 `domain`、`text`、`claims`，回到 5 / 25，`MECH-DC-001` 与 `MECH-DC-021` 都在人工。单发偏离不升级为稳定结论。

P-LAW-05 的反差最大：三次最终答复都拒绝，三次里只有第 2 轮没有先调用 `law_verify` 或 `law_search`。这说明模型知道结论，但在「不要调用工具」这个约束上不稳定。

## 本族结论

选择与参数仍是 12/12，本族的落差集中在三处：P-LAW-02 的题面路径与 `query`、P-LAW-04 第 1 轮的多余参数、P-LAW-05 的工具先行。前两处不影响工具选择，第三处直接决定拒绝率。

修复优先级：拒绝题的工具先行最值得先处理，它同时影响本族与权利要求、说明书两族；其次是 P-LAW-01 的 420 秒时限，需要判断是单次模型等待异常还是任务本身会拖长；P-LAW-02 属于冻结题面差异，随题面统一处理，本批不改。

成本上本族居中：总费用 0.3458 元，每成功任务 0.0226 元；失败样本费用 0.1653 元，接近成功费用，主要来自 P-LAW-02 的三轮与 P-LAW-05 的两次工具先行。
