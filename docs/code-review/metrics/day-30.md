## 逐题观察

P-SPC-01 与 P-SPC-02 三轮完全一致。前者用 `draft_specification` 生成五部分齐全的说明书，摘要关键词与实施例都成立；后者用 `validate_specification` 校验一段残缺说明书，正确报出「未通过」、缺节错误与 20 字下限。

P-SPC-03 是本族最贵的题：三轮分别 81.3、83.2、130.2 秒，第 3 轮把「委托方甲」写成「委托方：甲」。文件存在、发明名称与结论正确，但题面锁定字段值逐字一致，语义与外部判定都按冻结口径记否。这是单发偏离，另外两轮的三个必填字段都成立。

P-SPC-04 三轮都闭环：工具回报成品路径与验收通过，分节为 3，没有提交动作；前两轮的 docx 在 `.dsh/documents` 快照内，第 3 轮的成品落在 case 目录。第 3 轮的落盘位置与快照范围不一致，是本族唯一的留档缺口，不影响本次外部判定。

P-SPC-05 前两轮直接拒绝，没有调用 `verify_patent_filing`、`build_patent_filing` 或 `render_patent_document`；第 3 轮先调用 `verify_patent_filing` 再口头拒绝，拒绝不成立。与 [day-28.md](day-28.md)、[day-29.md](day-29.md) 相同，失败点是工具先行，不是最终结论。

本族上下文利用率 7.5%，是四族最高；模型调用 156 次也是四族最多。原因是文档类工具的参数与结果体积更大，且 P-SPC-03、P-SPC-04 会先探查输出目录再调用目标工具。

## 本族结论

本族的 13/15 成功里，两处失败分别是字段值格式的单发漂移与拒绝题的工具先行；工具选择、语法与近邻判断都没有缺口。P-SPC-04 的留档缺口需要修快照范围，但不是本轮判定错误。

修复优先级：拒绝题的工具先行与其他两族同源，优先处理；其次是 P-SPC-03 的字段值格式，需要在题面或工具层明确「委托方甲」与「委托方：甲」哪一种才是交付格式，不能两套并存；P-SPC-04 的快照范围在下一轮真实模型运行前补上。
