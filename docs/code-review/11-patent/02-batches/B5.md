## 采纳并修复（5 条）

- **F-PAT-081**（最重要）规格校验的两条数值路径完全不识别中文单位。共享词表的正则备选串只有拉丁单位，而同一模块的量纲表与新颖性轨的汉字单位表都收了中文单位；新颖性轨先匹配数值再向前读单位，规格校验要求单位紧跟数值，因此中文写法一条都匹配不到。实测 `厚度为20毫米至90毫米` 抽取结果为空，端点与中点检查静默不跑。修法是词表新增汉字备选串与合并串（`NUMERIC_HAN_UNIT_ALTERNATION`／`NUMERIC_ANY_UNIT_ALTERNATION`），两条路径改用合并串。
- **F-PAT-082** 权项特征按原文单位写法比对：权利要求写 `10mm`、说明书写 `10毫米` 会被判「技术特征未记载」。改为两侧都按规范单位键比对，且不做量纲换算（`10cm` 不覆盖 `100mm`）。
- **F-PAT-083** 权利要求引用正则漏「和／与／及／第／项／之／任／中」与范围连接符：「如权利要求1和2所述」「根据权利要求1至3中任一项所述」都漏报，而这是细则第二十条第三款的法条级检查。
- **F-PAT-080** 部分附图未参与分析时，附图说明里的标号被判成悬空 error：`unusable` 的图不贡献标号集合，悬空判定却照常计算，于是没读出来的那张图上「说明书写了、分析结果里没有」的标号被报成「附图中不存在」，结论方向与「分析不完整」的提示相反。改为有不可用图时跳过悬空与权利要求标号缺失判定。
- **F-PAT-084** 模糊词「可能」按子串匹配，误伤「尽可能」「不可能」「可能性」，与模块自述的「按上下文而非子串匹配」相矛盾；位置也因二次子串查找可能指到更早的「尽可能」所在行。改用上下文正则并以匹配下标定位。

## 未修（4 条）

- **F-PAT-085** 摘要未加括号标号的前瞻只认标点与空白，句中写法不报。去掉前瞻会把「包括2个」读成标号，扩字符集属于打地鼠，先要定组件标号的口径。
- **F-PAT-086** 背景技术把裸「标准」当作文献引证，「符合国家标准」也要求补出处。判据偏宽，是否必须写标准号需要产品口径。
- **F-PAT-087** SMILES 校验是文档化的空实现（RDKit 未打包），但报告里没有对应的未评估项；需要先有可靠的 SMILES 候选抽取。
- **F-PAT-088** 新颖性轨把中文单位区间读成两个数值点（探针：`20毫米至90毫米` 得到三个 `isPoint`）。两侧都写中文单位时可能把「覆盖」判成「不重叠」。修法会改变模型可见的新颖性摘要，需要连同 `numeric-range` 用例与快照单独一批处理。

## 观察（不构成发现）

- 权利要求引用的违规检查用 `exec` 只报第一处；同时存在多种引用写法时只列一条 error，这是有意的呈现收敛（一条足以要求修改）。
- `spec-types.ts` 全部是类型声明与常量，无运行行为。
- 本批 `v8 ignore` 均带理由说明（正则捕获组必然参与、schema 已拒绝非法输入），没有出现「用 ignore 掩盖未测分支」。
- `amendment-reserve` 的多处忽略同样挂在「正则捕获组必然参与」上，与 B3 的同类处理一致。
- 发布面变化：`patent-core` 根桶不再导出拉丁专用串 `NUMERIC_UNIT_ALTERNATION`（包内仍从定义模块导出，新颖性轨照旧使用），改用合并串 `NUMERIC_ANY_UNIT_ALTERNATION`。原因是修 F-PAT-081 时它已无外部消费者，而「只给拉丁单位」的公开串正是这次误用的来源。`verify-patent-core-exports` 现在全绿。
