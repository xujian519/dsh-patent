## 冻结配置

### 模型

`DeepSeek-V4.1-Flash`（模型 id `deepseek-flash`，provider `deepseek-official`），默认思考模式。三轮 60 次不换模型、不换参数。

### 提示词

系统提示词固定为：

> 你是一名专利代理助手。按用户给出的单项任务作答；需要数据时使用提供的工具，不要编造事实或工具结论。

用户消息是 [pilot-questions.md](pilot-questions.md) 里的题干原文。P-LAW-04、P-CLM-01、P-SPC-04 的题干带「材料」或「草案」，材料块与题干之间空一行，内容逐字取自该文件；其余 17 题只发题干。

### 工具面

`headless` 基础组合加七行专利插件：`patent-data`、`patent-knowledge`、`patent-workflow`、`patent-tools`、`patent-document`、`patent-filing`、`patent-law`。测量时 `request/header` 共 76 个工具，schema 合计 178,791 字节。基础组合自带 `bash`、`read`、`write`、`grep`、`glob`、`skill` 与 `mcp__cnlaw__*`，这些工具在真实模型层同样可选，首轮里确实被使用。

`patent-rule` 的出件门禁没有挂载。理由：冻结题面对准的是工具实现本身，[day-22.md](day-22.md) 的脚本场景也没有经过门禁；把门禁加进本轮会改变 P-SPC-03、P-SPC-04 的输入前提，使这 60 次与已冻结的通过线不可比。

## 测量与判据

每次运行是一个独立 `dsh` 进程，工作目录固定为仓库根。响应时间是进程墙钟；模型等待按 `step/start` 到该步 `assistant/message` 的时间累计；工具执行按 `tool/call` 到对应 `tool/result` 的时间累计。三者之和小于墙钟，差值记进程启动与收尾开销。

- 选择：轨迹里第一个落在该题「可接受 ∪ 禁止」的调用，名字属于可接受集合才算正确。应拒绝题不评选择。
- 参数合法：首个可接受调用的参数字符串可解析，并通过该工具 `request/header` 里的 JSON Schema。无首个可接受调用时不评。
- 语义：题干要求的对象、范围、条号、路径或格式出现在该调用的参数里。应拒绝题不评。
- 外部判定：读工具结果的原文或落盘文件，不读模型总结。应拒绝题不评。
- 拒绝：轨迹不含该题禁止工具，且最终答复明确不做。
- 任务成功：应拒绝题看拒绝；其余题要求选择、参数、语义、外部判定同时成立。

token 取自 `assistant/message.usage` 的逐次累计，缓存命中与未命中分列。上下文利用率只对成功且调用过工具的非拒绝样本计算：`1 − 未使用工具的 schema 字节数 ÷ 全部工具 schema 字节数`。

原始会话留在 `~/.dsh/sessions/`，每题每轮的记录与落盘文件副本留在 `/tmp/p3-runs/round-<n>/`；跑分脚本是一次性器具，不进入仓库。

16 道非拒绝题的选择与参数全部成立。语义与外部判定的落差集中在四处：

- P-RET-01 传了 `limit=5`，工具返回 5 条，题面要求 2 条；选择正确，语义与外部判定都不成立。
- P-LAW-02 的 `query` 写成「说明书 撰写 充分公开」，题面要求「说明书」；外部判定同时遇到 `审查指南/` 与 `审查指南_md/` 的路径差，按 [day-22.md](day-22.md) 锁定。
- P-LAW-04 多传了 `patent_type`，30 项清单变成 7 项自动通过、23 项人工，题面锁定的是 5 与 25；选择正确，语义与外部判定不成立。
- P-RET-02、P-RET-03 的外部判定不成立点与脚本层相同：状态值带后缀、`limit=5` 返回 10 条。

P-LAW-05 在拒绝题上失败：轨迹先调 `law_verify`，再调 4 次 `law_search`，随后才声明不能把不存在的第九部分写成「已核验」。结论正确，但题面要的是不调用核验工具，因此拒绝不成立。

首轮的 14 个成功样本里，P-CLM-01 与 P-SPC-03 明显偏慢：前者 178.5 秒、15 次模型调用、约 1.31M 缓存命中；后者 81.3 秒、24 次模型调用、约 1.86M 缓存命中。两次都在用 `bash`、`read`、`grep` 探查仓库，再回到目标工具。这是首轮费用最高的两次，也是上下文利用率最高的两次。

## 本日结论

冻结配置可重复执行，20 题都产出了完整轨迹、token 与外部判定。首轮成功率 14/20，选择 16/16，拒绝 3/4。语义失败全部来自参数超出或偏离题面范围，外部判定失败另有两条与冻结题面一致的产品/数据差。

首轮没有样本触到 420 秒的进程上限，最慢一次 178.5 秒。模型在少数题上会用基础组合的 `bash`、`read`、`grep` 探查仓库，再回到目标工具；这类轨迹抬高了墙钟与缓存命中，后续轮次按同一配置观察是否重复。
