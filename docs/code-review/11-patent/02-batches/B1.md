## 断言内容

1. 六个服务接缝在 isolate realm 内全部可解析：`patentData`、`patentKnowledge`、`patentWorkflow`、`patentTeams`、`patentRuleGate`、`writingPatterns`。
2. 15 个代表性工具各来自一个包，全部进入宿主 `tools` 注册表。
3. 工具注册无重复（重复即意味着同一行被挂载两次）。
4. **负控制**：置 `PATENT_MOUNT_DROP_TEAMS=1` 禁用 `patent-teams` 行后，探针必须报告 `patentTeams` 缺失、`awaiting` 含该名、且 `patent_teams_create` 不在工具集里。这条用例证明探针真的在观察，而不是恒真。

实测：2 条用例通过，用时 7.4 秒；web-app 全包 162 个用例通过。

## 装配过程中确认的两条环境事实

这两条决定了后续批次不能把它们当成专利域断链：

1. **headless profile 的宿主链根在 launcher。** `headless-startup` 注入 `cmdlineArgs`，`sandbox-policy` 注入 `headlessStartup`，`fs`、`working-directory`、`subagents` 依次依赖。测试驱动若不提供 `cmdlineArgs` 与 `appExit`，整条链挂起，`patent-teams` 因缺少 `subagents` 而不发布、`patent-tools` 因缺少 `workspaceRoot` 在 `apply` 抛错。这不是专利域缺陷——生产环境的 launcher 会提供这两个值，探针据此补上了 `prepare` 钩子。
2. **`patent-tools` 在无工作区根且未配置 `figureIndexFile` 时 fail-loud。** 报错为 `PatentToolError: 未配置 figureIndexFile 的绝对路径，且部署没有工作区根`。这是有意的 fail-loud（宁可加载失败也不写进程目录），不是缺陷；但意味着任何最小组合若跳过 workspace 相关行，必须显式给出输出路径。
