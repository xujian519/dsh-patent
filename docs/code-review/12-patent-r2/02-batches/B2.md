# B2 纯库叶子：methodology、patent-index-asset、writing-patterns、patent-fees、patent-deadline

执行日期：2026-11-28。范围是五个不含服务接缝的库包，共 37 个 `src` 文件（methodology 5、patent-index-asset 5、writing-patterns 7、patent-fees 7、patent-deadline 13）。第一轮登记后内容变更的漂移文件四个：`methodology/src/tool/triz.ts`、`patent-deadline/src/report.ts`、`patent-fees/src/compute.ts`、`patent-fees/src/tool/patent-fees.ts`，本批逐个精读；其余文件按 B0 台账已签收状态只做可达性与精简扫描。

## 实施的发现

### F-PAT-121（部分）：`limit` 非法时保留稳定错误码

`query_writing_patterns` 的 `limit` 校验原本抛裸 `Error`，`tool/result` 只能报成通用执行失败。现改为 `QueryWritingPatternsToolError extends HarnessError`，错误码 `invalid_limit`，消息文本保持 `query_writing_patterns: limit must be a positive integer, got N`，与 README「以点名该参数的工具错误返回」一致。工具 schema 与描述未动。

### F-PAT-136①：TRIZ 参数错误带稳定错误码

`triz` 的三处参数校验从裸 `Error` 改为 `TrizToolError extends HarnessError`：只给一个参数或两个都不给是 `invalid_parameter_pair`，参数越界是 `invalid_parameter`。消息文本不变，`render` 的穷尽性兜底仍用 `Error`，因为那是编译期不可达的编程不变量，不是模型输入错误。

### F-PAT-136③：索引资产文档漂移

`patent-index-asset` 的模块 JSDoc 与双语 README 只写 `patent-law`、`patent-fees` 两个消费方，实际 `legal-law` 也用 `readArticleEntries`、`IndexAssetError` 与全部字段读取器。已补齐第三消费方，并把错误契约一节的可捕获错误类型补上 `LegalLawBaselineError`；包描述由「patent domain」改为「patent and legal domains」。三处文案同步后重录 `README.i18n.yaml` 配对哈希。

## 待确认

**F-PAT-121 剩余两项模型可见文案**：

- 结果首行「命中 N / M 个模式」的 N 是 `limit` 截断后的条数，M 是库总量。改为「返回 N 个（库中共 M 个）」即可准确，无需改 `PatternStore` 接口；若要显示截断前的真实命中数，需要给 `search`/`match` 增加返回值。
- `category` 在三种模式下语义不同：`search` 下是过滤条件，`match` 下作为案件类型参与打分，`category` 下是列举对象。参数描述目前只写「Pattern category: …」，建议补一句按模式区分的说明。
