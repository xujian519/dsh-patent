# Agent Note: 上游 v0.1.7-alpha.1 同步

Status: implemented

[English](2026-09-22-upstream-v0.1.7-alpha.1-sync.md) | 中文

## 问题

本次同步把 fork 的跟踪点从上游的 `dsh-v0.1.6-alpha.2` 标签（即本次合并的基点）推进到 `dsh-v0.1.7-alpha.1` 发布。上游前进 1299 个提交，fork 自带 595 个，首次合并有 183 个路径冲突：fork 自有面 70 个、client 插件包 52 个、core 包 40 个、基础设施与配置 20 个，另有 1 个未归类。

本版有三处改动撞上了上游从未见过的 fork 内容。上游用一个声明插件（`@deepseek-ai/dsh-agent-preset`）加 `@deepseek-ai/dsh-agent-preset-registry` 取代了由插件声明预设的系统，并把随包发布的预设表移入 `packages/bundle/web-app/presets/`，由 bundle 通过 `dsh.bundle.patch` 声明；fork 的 `packages/preset/agent-presets` 包、它的 `presets/{patent,document}` 目录树，以及它所读取的 `$DSH_HOME/.agent-presets` 用户根目录在上游都没有对应物。上游还新增了两道只判定本 fork 才会产出的内容的门——`verify-v3-event-vocabulary` 把冻结的 V3 事件词表与一个钉住的 V3 writer 提交比较，`verify-no-unknown-casts` 的已提交基线只记录上游自己的断言——外加 `scripts/check-workspace-constraints.ts` 里按包推导期望的 `package.json` `files` 策略。

## 决定

- **上游的声明式预设系统取代 fork 的预设包，fork 的预设改由 web bundle 发布。** `packages/preset/agent-presets` 退役：它的 registry、session、display 与 inventory 源码并入上游的 `packages/preset/agent-preset-registry`，资产移入 `packages/bundle/web-app/`，成为 `presets/{patent,document}.patch.yml`、`presets/{patent,document}{,.zh}.md` 与 `skills/{patent,document}/`。合并后的树上没有任何东西读取用户根目录 `$DSH_HOME/.agent-presets`，`docs/patent-workbench-tasks.md` 把它记录过的每个路径改指 `presets/patent.patch.yml` 里的声明。
- **web bundle 发布 fork 的预设资产，约束表把它们记在上游自己的条目旁边。** `packages/bundle/web-app/package.json` 列出四个指南文件与 `skills`，`expectedDshPackageFiles` 从 `dsh.bundle.patch` 加 `packageFileExtras` 组合出期望，于是 `'@deepseek-ai/dsh-web-app': ['presets/patent.md', 'presets/patent.zh.md', 'presets/document.md', 'presets/document.zh.md', 'skills']` 与上游的 `'@deepseek-ai/dsh-agent-preset': ['skills']` 并列进表。发布该目录是必需而非整洁：`presets/patent.patch.yml` 用 `createRequire(baseUrl).resolve('@deepseek-ai/dsh-web-app/package.json')` 解析自己的技能根，再把 `skills/patent` 拼到该路径上，因此加载十五个专利技能的条目跟随已安装的包。
- **`RELEASED_V3_EVENT_TYPES` 收入 fork V3 writer 的二十个名字。** fork 的 V3 writer 在上游的 58 个名字之外写出了 `agent/request-error`、3 个 `patent/*`、9 个 `patent-teams/*` 与 7 个 `self-evolve/*`，而 `verify-v3-event-vocabulary` 要求与一个 V3 writer 提交精确相等，故该集合长到 78 个名字。pin 提交号留在发布校验里而不进源码树；删掉这些名字会让每一条已录制的 patent-mode 与 self-evolve 会话在迁移时被拒或改名。
- **三种 fork 专有的消息来源类型被定性为仅归因。** `docs/persistence-changes/2026-09-22-fork-source-attribution` 相对已接受的格式 4 基线记录 self-evolve、sidechat 与 patent-teams-report：每种类型都来自只有本树才发布的产出方，该产出方之外的读取者不会丢失信息，因此这些增加保持同版本而不需要格式 5。记录按类型陈述读取者承诺，不授予针对联合备选项的一般豁免。
- **未知断言基线是两父提交清单的并集，再裁剪到合并后的树。** `verify-no-unknown-casts` 随本版到来，因此一份只记录上游 565 文件与 1476 断言的基线对 fork 的清单（871 文件、2214 断言）没有任何条目，会把 459 条断言报成新增，而其中没有一条是新的。以并集重建并裁剪到合并后的精确清单（771 文件、1929 断言），得到一份能区分「继承来的断言」与「本次合并新写下的断言」的基线。有三个站点超出两父提交的清单，逐条复核如下：`packages/client/ui-session/tests/status-controller.client.spec.ts` 里的 `client.ctx.sessions as unknown as ClientSessions`（client 面把 `Context.sessions` 解析为 host 的 `SessionStore`，直接断言被 TS2352 拒绝；`packages/api/session-controller/tests/client-apply.client.spec.ts` 已因同一原因带同一断言）、`ui-todo-board` 一个操作数在两父之间移动的 board-view 用例，以及 `scripts/verify-agent-preset-config.spec.ts` 里的一个夹具——它的断言已由解析器新抽出的 `pluginConfigSchema(value)` 收窄步骤取代，因此该文件没有新增任何断言。
- **本版发布的 V4 关系约束落到 fork 已录制的夹具上。** `assertReleasedV4Relationships` 要求每个 step 之前有 `step/start`，并在 message 缺 `isError: true` 时拒绝带 `error` 的 `tool/result`，因此四个 self-evolve 夹具（`packages/self-evolve/self-evolve{,-basic}/tests/*.spec.ts`）把该标志从 content block 移到 message 上并为错误命名，`scripts/token-economy-baseline.spec.ts` 往它的明文日志夹具里补一个 `stepStart` 事件。fork 专有的 `suppression-reasons` 门补进 `scripts/run-gates.spec.ts` 的期望门序。
- **两处合并引入的克隆在源头修复，而不是抑制。** `jscpd` 把 `packages/client/better-sidebar/src/subagent-activity.ts` 导出的 `textBlockParts` 与同包 `tool-result-text.ts` 的 `toolResultTextBlocks` 匹配成一对（两份列表收拢文本块的方式相同，但四个调用点的拼接方式不同），又把 `scripts/verify-agent-preset-config.spec.ts` 里一段 schema 收窄代码与门自身的解析器匹配成一对。`subagent-activity.ts` 只保留 `contentText`，`sidechat-transcript.ts` 直接调用共享提取器，而 `pluginConfigSchema` 成为解析器与声明夹具共用的导出收窄步骤，于是该门报 0 克隆，既无 `jscpd:ignore` 标记，也未新增未知断言。
- **上游包内容在 fork 已记录改名的位置沿用 fork 的名字。** 上游的 `packages/guard/timeout-policy` 本版带着自己的改动到来；合并后的树保留 fork 的 `@deepseek-ai/dsh-timeout-guard` 名字，并把该名字套到上游最新的 `src/index.ts` 上（模块文档注释与注册的 `name`，13 行），因此上游的行为落地，而 fork 改名退役掉的那个名字不会复活。
- **桌面族接收上游发布，并在其上重新移植 fork 的能力。** 合并后的 `apps/desktop` 与上游相差 45 个文件，承载 fork 的品牌图标（`assets/icon.*`、`assets/tray*.png`）、`src/tray.ts`、`src/print.ts`、`src/bridge-server.ts`、`src/startup-deadline.ts`、unsigned 打包与强制更新的环境处理（`DSH_DESKTOP_UNSIGNED`、`DSH_DESKTOP_MANDATORY_UPDATE_TEST_ORIGIN`）及其 `package-target` 与 `installer-packaging` 规格，以及 desktop-host 的组合覆盖层 `apps/desktop-host/config/desktop.cordis.patch.yml` 与 `desktop-composition.spec.ts`。
- **版本族在合并提交内对齐。** 338 个 fork 清单原本停在 `0.1.6-alpha.2`，与上游的 `0.1.7-alpha.1` 并列；fork 唯一的版本镜像 `SIDEBAR_SERVICE_VERSION`（已随 PR #677 删除的 better-sidebar 包的 `service.ts`）随它们一起移动。随后 `pnpm exec tsx scripts/release/verify.ts --family dsh` 解析该族：352 个成员、单一版本、发布顺序可解。
- **读取已产出构建物的卫生门需要一次构建，而 fork 的 CI 车道本就承担它。** `publint`、`built package invariants` 与 `node-next types` 检查由 `lib/` 构成的发布面，因此在未构建的树上本地跑它们只会报缺文件，而不是合并缺陷；fork 的 `node-hygiene` 作业正是为此先跑 `pnpm run build`。

## 后果

fork 带着完整的预设、专利、桌面、better-sidebar、synapse、self-evolve、document、todo-board 与插件市场面发布上游的 v0.1.7-alpha.1 基线：44 个包只存在于本树，而上游唯一未被本树携带的包是 `packages/guard/timeout-policy`——它的内容以 `timeout-guard` 之名继续存在。预设现在是发布它们的那个 bundle 内部的声明，这意味着预设的技能随解析它们的包一起移动；fork 的专利与 document 预设遵循这条规则，而不是另设一个预设包。两道由上游自己的基线文件催生的门在能判定任何东西之前都需要一份 fork 侧清单，如今两者都比较记录下来的状态而非「不存在」：78 个 V3 名字与 1929 条断言。V3 的 pin 提交号不在本仓库里，因此重跑 `verify-v3-event-vocabulary` 需要从发布校验取号。

## 考虑过的替代方案

- **把 fork 的指南与技能排除在已发布的 web bundle 之外。** 否决：`presets/patent.patch.yml` 相对已安装的 `@deepseek-ai/dsh-web-app` 包解析 `skills/patent`，因此不发布该目录会把一个已发布的预设变成激活时失败的行，而 fork 早先的布局是把同样的指南作为 `presets/patent/README.md` 发布在自己的包里。
- **首次见到未知断言基线时就从合并后的树上裁剪它。** 否决：裁剪只能证明相对它起步的那份基线没有新增，而这里那份基线是上游的文件，于是每一条 fork 断言都会像本次合并写下的那样进入，三个真正新增的站点会与 456 条继承来的断言无从区分。
- **删掉 ui-session 的 client 面断言并断言 host 类型。** 以编译器证据否决：合并后的 client 程序把 `Context.sessions` 解析为 host 的 `SessionStore`，因此 `as ClientSessions` 与 `as ISessions` 都因 TS2352 失败，直接形式因 TS2339 失败，只剩 fork 的 session-controller 台架已在用的双重断言。
- **给未知断言基线添第四条 `verify-agent-preset-config.spec.ts` 断言，而不是抽出收窄步骤。** 否决：该夹具需要的是声明插件自己的 schema，而门的解析器本来就会读它，所以这条断言是可避免的、并非编译器所迫；一条基线条目会把它作为永久例外留存在三条编译器确实需要的断言旁边。
- **恢复上游的 `timeout-policy` 包名并退役 fork 的改名。** 否决：fork 在上游至今保留的 FIXME 之后记录了这次改名，取回上游的名字会为了零行为收益重开一个已定的命名决定，因为上游的源码除名字外原样转移。
- **在保留上游的声明插件与 registry 的同时恢复 fork 的 `agent-presets` 包。** 否决：上游的 registry 是合并后的树里唯一的预设声明读取者，保留两套预设系统会让 fork 自己的发现、挂载与创作路径失去消费者。

## 测试

`pnpm run test` 在合并树上跑完整单元套件：2238 个文件、41766 个用例通过，剩余两处失败属环境约束而非合并造成。`packages/util/http-proxy/tests/install.spec.ts` 在本机 DNS 延迟下 5 秒超时，单独跑同样失败（与上一次同步记录的是同一约束）；`packages/patent/patent-tools/tests/figure-freecad-real-render.spec.ts` 用 FreeCAD 自带的 Python 渲染中文标注，而 `LANG`/`LC_ALL`/`LC_CTYPE` 为空时该解释器把 `json.dump(..., ensure_ascii=False)` 按 ASCII 编码——同一规格在 `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 LC_CTYPE=en_US.UTF-8` 下 3/3 通过。`pnpm run typecheck` 覆盖两个面（退出 0）；`pnpm run lint` 在 5872 个文件上报 0 warning / 0 error；`pnpm run duplication` 报 0 克隆。`pnpm run hygiene` 报 19 门通过 / 0 失败 / 0 跳过，含 `constraints`、`publint`、`built package invariants`、`package invariants`、`no new unknown casts` 与 `Cordis config`。`pnpm run doc-sync` 报 44 门通过 / 0 失败 / 0 跳过,全语料配对检查 1372 对全部一致。`pnpm exec tsx scripts/release/verify.ts --family dsh` 解析 352 个成员、版本 `0.1.7-alpha.1`。`pnpm run persistence-changes --check` 接受所记录的迁移，`pnpm run verify-persistence-catalog` 报目录、双语页面、`known-event-types.ts` 与 schema 清单均为最新。
