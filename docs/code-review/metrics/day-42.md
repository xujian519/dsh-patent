## WF 失败链

WF-03 三次都正确调用 `flexible_plan`，题面没给 `stages`，工具返回「（无待执行阶段）」。结果文本明确写出零阶段，没有假装生成；这是题面把「建计划」当成「生成阶段」的判定差，[day-34.md](day-34.md) 已经改判，本日不列代码缺陷。

WF-04 的问题不同。第 2 次在一次 `transition` 调用里带了 `planSteps`，工具返回 `ok: true`，只做了 `planning → awaiting_approval`，任务同步没有发生。调用方拿到成功结果，无法知道参数被忽略；语义列因为参数确实出现而记「是」，把一次没有发生的同步算成了参数成立。第 1、3 次没有带 `planSteps`，语义记「否」，外部判定三次都按冻结文本记「否」。

WF-01 第 3 次的团队工具链是模型改道，不是代码缺陷；团队目录与计划文档是业务产物，按清单清理，不算资源残留。

## WF 代码证据

`packages/patent/patent-tools/src/tool/patent-plan-task.ts:215`–`:219` 把 `planSteps` 与 `previousTasks` 放在全 action 共用的参数表里。`:271`–`:309` 的 `transition` 只读 `tasks`、`feedback`、`issues`、`rounds`、`maxRounds`；`:310`–`:320` 的 `sync` 与 `replan` 才读 `planSteps`，并且都有「非空」校验。参数表与 action 的实际消费范围不一致，`transition` 对 `planSteps` 既不执行也不拒绝。
