# 交付质量门（P0/P1 自检）

交付前逐项核验；P0 全过才交付，P1 尽量满足并在交付摘要中标注未满足项。

这一层是**你的作业纪律**：P0 必须全部通过，任何一项不过都不交付。`document_deliver` 只在登记时另做一遍确定性核验（占位符、风格禁用词、空章节、断链、字数预算），把机器核验结论与你的 P0/P1 自述并列写入会话日志；它不核验这份自述，缺少的 P0 id 只作提示返回。

## P0（作业纪律：不通过不得交付）

`document_deliver` 的 `gate.p0` 填下面这些 **id**（`P0-1` … `P0-6`），不要改写措辞：工具拿这张表对照，会点名你漏了哪几项、哪些写法无法识别。对照只查写法与完整性，不查这些项是否真的通过——这些项是否通过，由你交付前的逐项核对决定。

- [ ] **P0-1 命名**：产物用规范名——`index.html` / `report.md`+`report.html` /
      `deck.html` / `<name>.docx`；路径在交付摘要中给出
- [ ] **P0-2 自包含**：HTML 单文件内联资源，不引用外部 CDN / 远程字体
- [ ] **P0-3 无占位残留**：正文不留残余占位符。哪些串算残留，以 `document_deliver`
      的工具说明与 `render_doc_template` 返回的 `residual` 为准，不要在本文维护第二份清单；
      复述这些串时用行内代码
- [ ] **P0-4 断链**：目录锚点、图片引用、站内链接全部可解析
- [ ] **P0-5 来源**：每个事实性断言（数据/日期/引用/版本）有可验证来源；
      无来源的断言已删除或标注"待核实"。URL 来源要用 `web_fetch` 打开原文核对，
      只凭 `web_search` 的摘要不算来源
- [ ] **P0-6 语言**：无错别字、无半角/全角混排硬伤、术语全文一致

## P1（尽量满足）

- [ ] 可访问性：语义化标签、对比度 ≥ 4.5:1、键盘可导航（Deck 翻页含键盘）
- [ ] 移动端：920px 断点重排正常，无横向滚动
- [ ] 字数预算：落在 brief 篇幅约束的容差内（容差见 `document_deliver` 工具说明）
- [ ] 单一强调色，每屏至多两处
- [ ] 每个 `<section>` 有 `data-doc-id`
- [ ] 文档含页脚（文档名 + 日期 + 版本）

## 工具侧确定性核验（机器执行，不看你的自述）

`document_deliver` 会自己读取交付文件并做一遍确定性核验，结论与你的 P0/P1 自述并列写入会话日志，交付物面板同时展示两列：

| 检查 | 判定 |
|---|---|
| 占位符残留 | 引用文本之外**阻断登记**；代码块或行内代码之内仅提示（复述规则时用行内代码写这些串）。判定哪些串，以工具说明为准 |
| 样式禁用词（`style` 指定的风格） | 风格标为 block 的词阻断登记，标为 warn 的仅提示 |
| 空章节（标题下无内容） | 提示 |
| 断链（本文档未声明的锚点） | 提示 |
| 字数预算（`char_budget`，容差见工具说明） | 提示；HTML 按剥离标记后的正文计 |
| 声明格式与扩展名不一致 | 提示，并**按扩展名核验**（`.html` 声明成 `pdf` 仍按 html 查占位符） |

阻断项会让 `document_deliver` 调用失败并列出位置；修复后重新登记。提示项不阻断登记，但应逐条修掉或在交付摘要中说明。这张表是工具核验的那部分；P0/P1 里的其余项（命名、自包含、来源、可访问性等）工具判不了，只能由你交付前自己核。

**无法核验（unreadable）**：工具读不出内容的文件（损坏的 `.docx` 等）必须在 `unreadable_ack` 里写一条 `path` + `reason_text` 才允许登记，否则调用被拒并给出建议；超出本部署读取上限的文件会写明"超过读取上限"并直接放行。`.docx` 会经 DOCX 文本投影后同样核验；pdf/pptx 等无文本读取器的格式标记为"未核验"，不得声称已核验。

`brief_ref` 指向不存在的文件只会提示，不阻断登记（brief 可能在本轮之前被清理）。

## 流程

1. 打开成品文件逐项核验（用 fs 读实际文件，不凭记忆）。章节文件（`chapters/**`）是工作稿：下面的 P0/P1 与 `document_deliver` 的机器核验都只针对最终成品。
2. P0 未过：立即修复后重跑本清单；仍有 P0 项不过就不交付。
3. 通过后交付摘要里附：文件路径清单、导出格式、未满足的 P1 项。
4. **登记交付物**：调用 `document_deliver`，`files` 列出全部成品与格式（path + format），
   `gate.p0` 填本次自己核过并通过的 P0 **id**（如 `["P0-1","P0-2","P0-3"]`）、`gate.p1` 填满足的 P1 项（无则省略），
   `brief_ref` 填 `brief.md`（若有），`style` 填本文使用的书写风格，`char_budget` 填 brief 声明的字数预算（若有）。
   工具会校验文件存在并跑确定性核验；报出阻断项或你自己不满意的提示项时，先修复再重试。
   工具不核验你的 P0/P1 自述，只把缺失或无法识别的 id 作提示返回，所以别把登记成功当成 P0 通过了。
   读不出内容的文件记得在 `unreadable_ack` 里写明原因，否则登记会被拒。
